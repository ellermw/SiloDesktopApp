## Root cause and correction

The C# launcher writes an initial scheduled result. The Windows PowerShell helper then replaces it using `File.Replace(temporary, target, $null)`. Windows PowerShell coerces that string argument to an empty backup path, which .NET rejects. Its error handler calls the same broken journal function, so the failure result is stranded in a temporary file and setup never starts.

Use `[NullString]::Value` to pass an actual null backup filename. Keep atomic journal replacement and existing path checks. New regression cases run the real journal functions in Windows PowerShell with both an existing scheduled result and an initially missing result, then exercise waiting/installing/completion writes and verify the journal, log and absence of stranded temporary files.
