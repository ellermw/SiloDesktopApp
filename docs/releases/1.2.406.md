# 1.2.406 — accurate queued traces and verified code cleanup

Twenty concrete modifications and removals over 1.2.386 give 1.2.406. Related tests and build attempts are not counted separately. Cleanup entries remove unused code; they do not claim new user features.

1. Remove DirectStreamProxy's unused cleanup-task field while retaining asynchronous cleanup.
2. Remove HlsProxy's unused cleanup-task field while retaining asynchronous cleanup.
3. Remove LibraryGridCard's unused customization-service lookup and field.
4. Remove MpvVideoHost's unused WS_VISIBLE constant.
5. Remove MpvVideoWindow's unused WS_VISIBLE constant.
6. Remove MpvVideoWindow's unused WS_EX_NOACTIVATE constant.
7. Remove MpvVideoWindow's unused GWL_STYLE constant.
8. Remove the unused fullscreen saved rectangle and its unnecessary GetWindowRect call; exit still matches the parent window.
9. Remove the unused recipe-dialog EditableFilterRule type.
10. Stamp queued player trace lines when the event is recorded, rather than when a delayed flush writes them.
11. Serialize queued batch draining and writing so overlapping flushes cannot reorder their batches.
12. Make an explicit queued flush wait for an earlier in-flight write to complete.
13. Avoid allocating batch collections for an empty queued flush.
14. Preserve the direct logging exception boundary while forwarding to timestamped writes, correcting a regression found during review.
15. Remove the unused TranscodeQualityPolicy and its obsolete dedicated tests; live quality changes use server replanning.
16. Remove the unused OAuthCompletionUrl and its obsolete dedicated tests; live sign-in uses native PKCE.
17. Remove the unused v2 PlaybackStartRequest model.
18. Remove its unused MpvNativePlaybackCapabilities.ApplyTo helper; capability checks now exercise the live v3 builder.
19. Move the still-used HDR/audio capability definitions into their own file, preserving their names, namespace, properties and defaults.

20. Let periodic timer callbacks skip a busy queued flush, preventing repeated timer work from waiting behind stalled disk I/O while explicit flushes still wait.

Independent source, XAML, Lua and reflection-caller reviews accompany Windows tests and native/published-payload verification. A synthetic reproduction against the exact published 1.2.386 PlayerService delays a queued flush and observes an event timestamp about 620 ms late. The new fixture verifies event timestamps and existing redaction through the actual PlayerService entry points. A deterministic blocked-writer regression verifies that an explicit flush waits; removing serialization makes that test fail. A null-batch test caught the direct-log exception-boundary regression before integration.

These are best-effort diagnostic logs. Queued data can still be lost on a process crash or failed disk write, and direct writes may appear physically before earlier queued events. This release does not claim to fix a particular buffering incident. Playback protocols, native engine, update helper and real elevated-install verification limits are unchanged. No running user app is closed or replaced by release publication.

Before publication, automated PR review identified the periodic callback contention. The sealed405 candidate remains an unpublished baseline: its actual PlayerService timer callback blocks behind a held writer in the native fixture.406 corrects that additional behavior and is built separately;405 is not a release.
