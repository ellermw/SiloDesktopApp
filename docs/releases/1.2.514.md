# Release 1.2.514 — consistent Silo taskbar identity

Three concrete behavior changes over published 1.2.511:

1. Keep the bundled Silo icon on the desktop window and taskbar after sign-in, server-branding refreshes and sign-out. Server wordmarks and branding inside the app remain available; server favicons are no longer fetched or converted for the Windows app icon.
2. Use the same stable Windows application ID for the client process, window, Start menu shortcut and desktop shortcut, so a correctly pinned Silo window groups with its launcher. Release window-owned Shell properties on final close.
3. Give pins created from the running window a Silo display name/icon and a relaunch command targeting the registered installation's stable launcher. This avoids binding new pins to a version directory that may later be removed. Unregistered development builds retain their own executable target.

An existing pin can retain Windows' old shortcut metadata. After updating, unpin the old entry once, launch the updated app and pin it again. This release does not rewrite the user's existing pinned shortcuts or restart Explorer.

The 1.2.511 hidden-window regression reproduced both server-icon replacement and missing taskbar/relaunch properties. Verification of the sealed corrected package is recorded in [current development](../current-development.md) with its installer checksum and public-delivery receipts after delivery. Physical taskbar pin/unpin/relaunch on the owner's machine remains a separate observation.

The immutable protocol 1 bootstrap, changed-file updater, subtitle continuity, playback authority and installer cleanup protections are retained. No installed application is closed, restarted or controlled by release verification.
