# Release 1.2.515 — Silo icon on the update progress window

One concrete behavior change over published 1.2.514: explicitly use the bundled Silo icon for the separate **Updating Silo** window's title bar and taskbar. The helper resolves the icon from its version-local client assets, independently of the caller's working directory. A cosmetic icon-loading failure does not stop the update flow.

The executable already embedded the Silo icon, but WinUI's progress window had no explicit window icon. The native regression reproduces that missing icon on the published 1.2.514 helper and checks corrected small/large icon pixels, centering, progress, error presentation and actionable controls without starting an installer or elevated worker.

An update is presented by the helper from the currently installed version. Consequently, the window installing this release can still show the older generic icon; updates started after this corrected helper is installed use the Silo icon. The owner's screenshot confirms an actual visible installation-progress phase, but successful completion/reopening is not inferred from that image.

The main app's Silo taskbar identity, stable launcher pinning, centered keep-open updates, subtitle continuity and all prior update/installer safety behavior are retained. The immutable protocol 1 bootstrap is unchanged. No production setup, app control, taskbar-pin rewrite or Explorer restart is performed during verification.
