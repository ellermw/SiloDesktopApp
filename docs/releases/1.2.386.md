# 1.2.386 — Gregorian calendar dates and installer error capture

Eight concrete behavior changes over 1.2.378 give 1.2.386. Tests and build attempts do not add version increments.

1. Format the requested week start as a Gregorian date in every regional culture.
2. Keep week-navigation date arithmetic Gregorian when formatting its result.
3. Generate all seven navigator dates in the server's Gregorian format.
4. Compare today's Gregorian date consistently for the Today marker.
5. Use Gregorian month names with Gregorian day numbers in day headings.
6. Use Gregorian month names and years in week-range labels.
7. Use Gregorian weekday labels in the week navigator.
8. Read Inno Setup's captured native error immediately after checking a path, avoiding a separate GetLastError call whose value may have changed.

The published 1.2.378 app reproduced a real ViewModel request failure under Thai culture: the requested week became 2569-10-26 through 3112-11-01 instead of 2026-10-26 through 2026-11-01. This was reproduced using synthetic HTTP responses, without changing Windows regional settings or contacting a user's server. The new native fixture exercises actual request/loading/navigation and CalendarPage rendering under Thai, Saudi Arabic, Persian and US English cultures at compact and desktop widths. These checks do not certify complete visual parity or live-server behavior.

The installer change is a documented error-capture robustness correction, not a claim that an overwritten-error failure was observed in the field. Isolated Inno fixtures verify captured native errors 2 and 3, directory guards, fresh installation, clean upgrade and preservation of untracked files on uninstall. Production elevated installation remains a separate verification limit. The playback engine and update helper are unchanged.
