1. Send GitHub's validated ETag in subsequent update checks to reduce metadata transfers.
2. Reuse the validated release/no-update result on304 without discarding a staged installer; invalid replacement metadata cannot replace that cache.
3. Recognize429 and rate-limited403 responses and explain the network limit in update details.
4. Use Retry-After seconds or HTTP dates for cooldowns.
5. Use GitHub's UTC rate-limit-reset header when no Retry-After is supplied.
6. Bound rate-limit waits between five minutes and six hours; ordinary errors retain the five-minute retry.
7. Wait for an in-flight manual check or download before choosing the automatic check's next interval.
8. Enforce the absolute cooldown before every metadata request, including manual checks and previously scheduled automatic ticks. Download progress/errors cannot erase it; cached manual download and installation remain available.
9. Fall back safely when reset timestamps are malformed or outside the supported date range.
