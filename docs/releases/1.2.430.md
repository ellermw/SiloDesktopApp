# 1.2.430 — profile avatars and room-navigation ownership

Twenty-four concrete changes over 1.2.406 give 1.2.430. Related regression tests, assertions and build attempts are not additional increments.

1. Resolve avatars returned by the authentication profile list.
2. Resolve avatars returned by ordinary and captured-authority profile creation.
3. Resolve avatars returned by profile-update overloads.
4. Resolve avatars returned by ordinary and captured-authority avatar uploads.
5. Resolve avatars returned by avatar deletion.
6. Resolve avatars returned by the Settings profile list.
7. Resolve avatars returned by Settings profile updates.
8. Resolve root-relative and protocol-relative server URLs consistently across platforms.
9. Recognize bundled SVG presets and DiceBear SVG URLs.
10. Decode cached SVG bytes with the native SVG image source on its owning dispatcher, retaining redacted failure diagnostics.
11. Use the shared image converter for the Settings overview avatar.
12. Use the shared converter for Settings profile cards so malformed/relative URLs cannot abort the remaining cards.
13. Capture avatar-response authority before dispatch, reject displaced responses and resolve against the initiating server.
14. Ignore stale Settings profile results and identity-change cancellation.
15. Publish SVG load outcomes to the shared artwork fallback mechanism.
16. Prevent a departed room page from reattaching its auto-start handler while preserving the current off-page room.
17. Give room joins coordinator-wide ownership so a late older page cannot replace a newer room.
18. Retire pending joins when the room is cleared or another room is adopted.
19. Bind join ownership to the account, profile and configured server.
20. Use separate view models for different rooms and detach old page subscriptions when rebinding.
21. Capture the joining view model for asynchronous continuation and cleanup, protecting a newer page's model.
22. Guard room-detail/suggestion initialization with its current generation, API authority and join ownership.
23. Recheck ownership before socket restart, and invalidate initialization/adoption on disposal or room end.
24. Keep queued playback-start callbacks bound to the room that requested them.

The exact published 1.2.406 app reproduces the Settings failure with an Invalid URI error and zero profile cards when a preset avatar is relative. The original PR46 room code also reproduces a late room A replacing already-joined room B. A separate baseline verifies the stale page-handler leak. Regression fixtures use actual native pages and coordinators with synthetic HTTP responses, isolated caches and offscreen windows.

Avatar verification covers card construction, SVG rendering, uploaded PNG decoding, failed-SVG fallback outcomes and independent generated-avatar variants. Public official preset and DiceBear sample bytes are checked separately from synthetic pixel fixtures. The avatar server contract reference is official Silo main `5444ec630d16d0a20dc919aef3c14bc76b2fc625`.

Room verification covers delayed capabilities, delayed joins, a prior shared room, clear, identity change, end during join, and leave/reopen handler ownership. It does not establish a physical multi-client playback start or live-server interoperability. The intended coordinator fallback for the current off-page room remains enabled.

The sidebar's separate cached-file SVG fallback remains outside this repair. Complete visual parity, physical hardware/phone behavior and production elevated-update verification retain their separate limits. Release publication does not install, close or restart the running player.
