## Scope

`/admin/settings/downloads` (Manage > Downloads > Settings) edits the **server's** `download.*` configuration only. It never reads or writes the signed-in user's own offline-download folder or device settings (verified in the native group by comparing the local settings files before and after, and by recording every request: only the admin settings endpoints are used). Whole Prepared Files administration (D1) is a separate lane; the page's "See storage on the server and nodes" link therefore opens `/admin/downloads` only when that route is registered and is shown disabled with an explanation until then.

## Delivered behavior (all 13 keys, official order and text)

Essential group "Downloads": `download.enabled` (Allow downloads), `download.transcode_enabled` (Prepare device-friendly copies), `download.max_concurrent_prepares` (Files prepared at once, a plain number: **0 means the built-in default of 2, not Unlimited**), `download.artifact_dir` (Prepared file directory), `download.artifact_max_bytes` (Default storage budget per location, decimal GB with an Unlimited switch), `download.artifact_disk_ceiling_percent` (Disk ceiling (%), 50 to 95), `download.server_bandwidth_mbps` (Server bandwidth, Mbps, Unlimited switch).

Advanced (collapsed by default, persisted, forced open by a dirty field): **Per user** `download.user_bandwidth_mbps`, `download.max_concurrent_per_user`, `download.max_per_period`, `download.period_duration`; **Whole server** `download.local_transcode_fallback` (blank reads as on), `download.artifact_cache_hours` (0 to 720).

- Unlimited/limit semantics: `0` is the unlimited sentinel on the five limit rows; the box is disabled with an "Unlimited" placeholder, unchecking restores the limit Unlimited replaced (an empty box when none was remembered, which blocks Save with an explanation).
- Unit conversion: GB are decimal (1,000,000,000 bytes). Typed text converts with exact decimal arithmetic (half-up to whole bytes); stored bytes display rounded to three decimals (`53687091200` shows `53.687`). A draft that still round-trips is kept so `1.` and `1.50` survive keystrokes.
- Directory: the placeholder shows the real effective path derived exactly as the server does (`silo-download-artifacts` sibling of the cleaned saved `playback.transcode_dir`, read-only here); "Reset <label> to default" appears only while overridden and stages the blank value; the Restart chip follows `restart-keys`.
- Validators mirror the server's `NormalizeAdminSetting`/`LoadFromDB`: integers (Go `Atoi` grammar, int64), ceiling 50 to 95, cache hours 0 to 720, bandwidth up to 73,786,976,294,838, durations in Go `time.ParseDuration` grammar plus whole `Nd` days and strictly positive, `max_per_period > 0` requires a positive period, a directory must read as absolute. Only edited keys are checked (a legacy saved value is never blamed); an invalid draft shows an inline message and keeps Save disabled; the server remains the authority and its refusal is shown without raw server detail.
- Dependencies: the official page edits every row regardless of `download.enabled`; this page does too. A server without the capability, a forbidden admin, an unverified profile or a demo restriction hides the editors and explains the recovery.
- Environment-managed keys (from `sensitive-status`, normally none for these keys) are disabled, explained and never written; an unreadable status or restart list does not block editing, as in the official page.

Shared behavior reused unchanged: `AdminServerSettingsApi/Store`, `AdminSettingsForm`, `AdminAuthorityLifetime`, the settings row/group/SaveBar primitives, gutter scroller and dirty-departure dialog, one strong `If-Match` write of only the dirty keys, conflict/unknown outcomes that keep the draft and require explicit Reload (no authentication replay, no automatic retry), late edits that stay dirty over the acknowledged canonical values, retirement that clears values/drafts. Additive shared changes: `AdminSettingsRow` gains an optional unit slot and inline error line; `LoggingDisclosurePreferences` accepts a `downloads` section; registration, text, installer `.xbf` allowlist and the surface manifest list the new files.
