## Expanded marker detection: inherited behavior plus a concrete existing integration risk

Upstream now detects episode credits from chapters/audio/visuals and movie credits on a best-effort basis. It independently controls local intro/credits detection, merges adjacent credits chapters, excludes credits-scene chapters, and caps ambiguous Ending/Outro chapters at three minutes. These are server algorithms, not algorithms to duplicate in the player. See [marker API](https://github.com/Silo-Server/silo-server/blob/ad899be9d4fd9f33d4b9e9ac6873166026661c6d/docs/markers-api.md#L35), [credits chapter classification](https://github.com/Silo-Server/silo-server/blob/ad899be9d4fd9f33d4b9e9ac6873166026661c6d/internal/intromarkers/credits_chapter.go#L40), and [on-demand local analysis and notification](https://github.com/Silo-Server/silo-server/blob/ad899be9d4fd9f33d4b9e9ac6873166026661c6d/internal/api/handlers/playback_lazy_markers.go#L245).

The desktop already consumes initial marker segments and keeps separated occurrences distinct (`src/SiloPlayer/Services/PlayerService.cs:951`, `:5120`; `libs/mpv/scripts/silo-osc.lua:3692`). **However, its existing live update path is incomplete:** `ApplyRealtimeMarkersUpdated` at `PlayerService.cs:6770` updates only legacy single ranges, never replaces `version.MarkerSegments`, and never calls `SendMarkersToOsc`. That send has only its startup caller at `:2158`. `MarkersChanged` refreshes the native overlay at `src/SiloPlayer/Controls/PlayerOverlay.xaml.cs:343`, but `ActiveMarker` and the Lua OSC prefer the existing segments collection. Thus adding, changing or withdrawing markers during playback can leave the authoritative segment consumers stale.

This is a pre-existing source-confirmed integration risk exposed more often by the new detection work, not a new wire contract. The server already sends the complete `marker_segments` array, including empty arrays on withdrawal: [realtime payload](https://github.com/Silo-Server/silo-server/blob/ad899be9d4fd9f33d4b9e9ac6873166026661c6d/internal/playback/realtime.go#L139), [notifier](https://github.com/Silo-Server/silo-server/blob/ad899be9d4fd9f33d4b9e9ac6873166026661c6d/internal/playback/marker_update_notifier.go#L114).

Fold a focused fix/check into the existing playback-marker package (small-to-medium): adopt the complete array, propagate it to both native/Lua consumers, preserve per-occurrence auto-skip state, and handle a withdrawn/empty set. Test a movie starting without credits, an episode with an online intro receiving local credits later, updated/removed credits, inactive file versions and edition changes. Recheck post-credit scenes and Next Episode/Skip Credits behavior. No runtime failure was reproduced here.

New `redetect-markers` and capability flags (`movie_credits`, `redetect_markers`, `detection_kind_settings`) exist in [admin_catalog_intro.go](https://github.com/Silo-Server/silo-server/blob/ad899be9d4fd9f33d4b9e9ac6873166026661c6d/internal/apiv2/admin_catalog_intro.go#L44).
