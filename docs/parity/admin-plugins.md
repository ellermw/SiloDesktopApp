## Scope

`/admin/plugins` (board with Installed and Catalog tabs, searches and filters, community-catalog control, install from a file, repositories) and `/admin/plugins/:pluginId` (an installed plugin's page, or a preview of a catalog plugin), registered through `AddAdminPlugins()` into the real Admin shell. Old `?configure=<id>` links are forwarded to the plugin's page. Plugin Apps (pages that plugins contribute) belong to another family: a plugin's admin routes appear in its More-actions menu as real entries that stay disabled with a tooltip.

Files: `AdminPluginsApi(.Uploads)`, `SiloApiClient.AdminPlugins`, `AdminPluginsModels`, `AdminPluginsController`, `AdminPluginConfigDraft`, `AdminPluginPresentation`, `AdminPluginMarkdown`, `AdminPluginsText` (all 249 `web.admin.plugins.*` messages plus the few `web.admin.errors|common|tasks` ones the page shows, verbatim), and `AdminPluginsPage` (`.cs`, `.Board`, `.Detail`, `.Sources`, `.xaml`), `AdminPluginConfigView`, `AdminPluginsUi`, `AdminPluginsRegistration`.

## Behaviour and rules

- Install, update, enable/disable, restart, uninstall, policy, configuration, bindings, repositories, catalog setting and upload each go out once: no replay after a timeout or token refresh. Each acts on the row that was on screen and confirmed (`AdminPluginPin`: plugin, version, source, repository, recorded update); if the list changed meanwhile, nothing is sent. A 4xx other than 408 is a refusal (the server's reason, redacted, retryable); a timeout, transport failure, 5xx or untrustworthy receipt is an unknown outcome that blocks that plugin (an upload blocks every lifecycle write) until it has been read back, and the read-back starts at once. A catalog-setting 412/428 needs an explicit reload.
- Every install, update and upload shows a confirmation with source, notice, version and publisher. Official: only non-Silo catalog tiles confirm; the update menu item and Silo installs act directly. The notices are the official strings, unchanged.
- Upload: size (256 MiB, the server's limit) and name are checked from the picker's own answer before the file is opened; there is no extension rule because the server takes a zip or a binary. The OS picker sits behind `FilePicker`; the stream is opened only after confirmation, read once in 512 KiB chunks (halved on 413), closed afterwards and forgotten; names and bytes are never logged or written.
- Configuration (`AdminPluginConfigDraft`, port of PluginConfigForm/SchemaForm/schemaFormUtils/configSchemaAdminForm): control types TEXT, TEXTAREA/multiline, PASSWORD/secret, NUMBER, SWITCH, SELECT, MULTI_SELECT, sections (collapsible, default collapsed, forced open by an error), `show_when` on fields and sections, validation (required, pattern, min/max length, min/max), declared JSON types incl. typed arrays and local `$ref`/enum item types, defaults, explicit clears for emptied non-secret fields, blank secret omitted, `clear_secrets` only by choice, managed fields never sent or cleared, "Check Connection" only when supported. The draft starts from the raw saved values; dirty means "differs from the start" (a control reporting its starting value never marks it edited). A secret is never filled in from the server or a default, survives a refused save, and is erased when the form is rebuilt from different data, closed, or the page/account/server changes.
- Untrusted text (names, summaries, Markdown, reasons, errors, URLs) is always plain `Run` text; Markdown is the official small reader (paragraphs, lists, strong, emphasis, code, links); a link exists and opens only if it is http/https without credentials (`ExternalBrowserUrlPolicy`) through the page's `Launcher`. Server and runtime text is redacted (typed secrets, credential-looking pairs, userinfo, signed query values) before it is truncated.
- Update check: `check_plugin_updates` is read and run through the Tasks API, polled every 3 s for at most 60 ticks while the page is open; when a run ends the lists are read again.

## Deviations from the official page (deliberate)

1. A failed installations read shows its error with Retry; the official board would show an empty inventory. Each other section (catalog, repositories, community setting, provisioning) shows its own failure with a reachable Retry and keeps older data.
2. Confirmation before every install/update/upload (see above).
3. Save and Check Connection are blocked while a visible field has a client error (the official shows the same errors but still sends).
4. Tiles are drawn 60 at a time behind a Show more button (the official draws all); reads are bounded to 20 pages of 100 per collection (the official drains 100 pages).
5. Tab changes replace the route in place instead of pushing history; the back link restores the board's search and filters through a static hand-over.
6. Capability icons are shown as their labels; the monogram is two letters as in the official page.
7. The official has no repository edit, so none exists (the earlier source had one). Removing a repository is immediate, as in the official page.
8. Notices stay until dismissed or replaced (the official uses toasts).

## Independent review of November 20 and its fixes

An independent read-only review of commit `2bba737ad` against official `df37bfc6d57b1680c0f7a59e51e15c8d0cfa6065` found no P0 and six defects (three P1, three P2). Between 3516fb41e and df37bfc6d only two cosmetics changed for these pages (a scroll margin in `PluginDetailSections.tsx`; the uninstall confirmation button uses the destructive variant in `AdminPluginDetail.tsx`); the native uninstall confirmation already used the app's destructive button style, so nothing changed for it. All six defects were confirmed in the code and fixed, each with tests (listed after the fix):

- **D1 typed secrets after a save.** A save the server accepted, or whose outcome is unknown, now erases everything typed (password boxes, text boxes, the draft) and the page draws the form again from what it read back, even when the stored values and `configured_secrets` are identical to before (the fingerprint-reuse check no longer applies to a settled form). After a definite refusal or a save that was never sent the typed values stay for the corrected retry. `AdminPluginWriteOutcomes.SettlesTypedValues` is the one rule; the repository form (an address can carry a credential) follows it too. A refusal that reads the installation back after a 409 follows the new installation, as the official form does. The connection check keeps its typed values (it changes nothing) and its copies are cleared. Tests: `AdminPluginConfigDraftTests` (four outcomes, same-fingerprint case), `AdminPluginsTests` (outcomes through the controller, unconfirmed block), native steps for all four outcomes with an identical re-read and for the repository form after a lost answer.
- **D2 multi-select lost write.** `SetOption` adds or removes only the clicked value and keeps stored values the options do not list, in stored order. Generalised: a field the admin did not touch is sent back exactly as stored (a select value outside the options, a number outside its range or beyond double precision, an over-long string, an unknown control type, an array on a text control), and a changed list keeps its untouched stored items as stored (numbers stay numbers). Tests: `AdminPluginConfigDraftTests` (list order, numeric and odd items, typed lists, managed list, every control type), native tag steps.
- **D3 text from plugins, publishers and repositories.** `AdminPluginPresentation.Clean` is the single gate: control characters, U+2028/2029 and the direction controls (U+200E/F, U+202A–202E, U+2066–2069, U+061C) become spaces, runs collapse, the result is trimmed and bounded. Names, publishers, repository names and URLs, versions, capability labels and descriptions, config titles, form labels, descriptions, option labels and placeholders, provisioning text and server/plugin error text pass through it (`Redact` ends in it; every string value inserted into a message by `AdminPluginsText` does too). Markdown keeps its own line breaks but loses direction controls. Install, update and uninstall confirmations open with the plugin ID and version on their own lines from the app's data; an upload file name with such characters is refused. Tests: `AdminPluginConfigDraftTests` (the review's examples, bounds, surrogates, messages, errors, README), `AdminPluginsSourceTests`, native install/update/uninstall confirmations of a hostile name and publisher.
- **D4 managed fields.** `Errors()` skips environment-managed fields, so a locked field failing its own rule never blocks Save; managed fields are never sent. Tests: draft unit test, native managed-plugin save.
- **D5 task-binding message.** A separate `Kind.TaskBinding` uses `web.admin.plugins.hooks.plugins.taskBinding.unconfirmed`. Test: `AdminPluginsTests`.
- **D6 upload deadline.** The 10-minute deadline over the whole upload is gone; each request (session, chunk of at most 512 KiB, completion) has its own limit in `AdminPluginSendAsync` (3 minutes), and the upload still ends on cancellation or when the authority is retired. Still one send per chunk, no replay. Tests: `AdminPluginsCommandTests` (slow but steady upload longer than the per-request limit, stalled chunk, caller cancel, authority retirement), `AdminPluginsSourceTests` (no overall deadline).

Decision recorded: a stored value that fails the form's own rule on a field the admin can edit still shows its error and blocks Save until corrected (existing assertion, unchanged); it is never blanked or altered. No existing assertion was changed.
