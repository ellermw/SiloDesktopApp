## Implemented transport contracts

[api/v2/shuffles.ts](https://github.com/Silo-Server/silo-server/blob/22e3a0ba7c1431dda77b957ed1012508d23f2b80/web/src/api/v2/shuffles.ts), [queries/shuffles.ts](https://github.com/Silo-Server/silo-server/blob/22e3a0ba7c1431dda77b957ed1012508d23f2b80/web/src/hooks/queries/shuffles.ts) and [ShufflePlayingNext.tsx](https://github.com/Silo-Server/silo-server/blob/22e3a0ba7c1431dda77b957ed1012508d23f2b80/web/src/playback/ShufflePlayingNext.tsx) are the current shuffle contract. Added `ShufflesApi`, wire models, a focused `ShufflePlaybackController` and `PlayerService.Shuffle.cs` instead of inferring random choices locally.

Allowed scope kinds are exactly `library`, `series`, `season`, `library_collection`, `user_collection`; generic `collection` is invalid. Creation sends `{scope:{kind,id}}`; create/read/advance/skip use `image_size=large`; advance sends `from_content_id`, skip sends `next_content_id`, and delete has no image query. The server owns eligibility, order and idempotency. Every pick starts from zero. A singleton next=current yields Finished rather than replay; post-roll refresh reads current eligibility; a 409 read drops the cached pick while other failed reads retain it. Pick Another uses the known next content ID. Explicit Stop retires local authority before deleting and releasing the player; ordinary close retires local state without inventing a server delete. Late reads, starts and mutations are rejected after close, cancellation, newer operations, profile/server changes or a superseding play request. A failed new scope retains an already running shuffle.

Public seams for the owner's UI integration: `StartShuffleAsync(ShuffleScopeRequest scope, CancellationToken ct=default)`, `ActiveShuffleId`, `IsShufflePlayback`, `ActiveShuffle`, `ShuffleNext`, `ShuffleScopeLabel`, `ShuffleChanged`, `RefreshShuffleNextAsync()`, `PickAnotherShuffleItemAsync()`, `StopShuffleAsync()`. `ShuffleScopeRequest` is the record `(string Kind,string Id)`. Existing `ContinuePlayingNextAsync()` dispatches to server advance for shuffle. Existing next-item metadata properties project the server choice: episode still versus movie backdrop, episode series versus movie title, and runtime minutes converted to seconds. Ordinary next/previous episode lookup is suppressed while shuffling. Library scope IDs are carried into watch preparation; other scope kinds do not invent a library ID. The root owns ItemDetail/Library/Collection entry gates, origin/back-stack retention and MainWindow's post-roll scope/action presentation and dispatcher.

[WatchPlaybackChrome.tsx](https://github.com/Silo-Server/silo-server/blob/22e3a0ba7c1431dda77b957ed1012508d23f2b80/web/src/playback/WatchPlaybackChrome.tsx) lines 147–183 and 916–946 preserve a multipart item's next file before advancing the shuffle; early shuffle post-roll waits for the final part. Native previously continued only audiobook parts. Added `PlaybackPartSequence` to order the matching edition's parts, prefer the next part's default file and fall back to its first authorized version. At a true video end, native continues that file with library/shuffle context and zero start; it does not advance on a premature stream end or room-owned completion. Explicit file selection also searches the authorized variant parts. Existing audiobook part handling remains separate and retains its library hint across user seeks and automatic part continuation.

Independent source review found a post-roll race: an Advance request can be pending when the old video's EOF reopens the overlay and its passive Refresh increments the same revision, retiring the server mutation's response. The controller now separates passive read order from mutation/ownership revision. Passive refresh is deferred while the current authoritative mutation is pending, and a read sent before a mutation cannot overwrite its result. A small state gate makes authority checks and snapshot commits atomic with Leave/Attach; mutation completion only releases its own pending marker. Close/profile replacement still retires the mutation rather than playing its late result. Controlled delayed Advance+Refresh, Skip+Refresh with successful/stale-close outcomes, and a pre-Advance read completing afterward are staged regressions; no execution is claimed.

## Library/file preparation and reader navigation

The current `getWatchState` schema permits optional `library_id` and `file_id`; [catalogRead.ts](https://github.com/Silo-Server/silo-server/blob/22e3a0ba7c1431dda77b957ed1012508d23f2b80/web/src/hooks/queries/catalogRead.ts) permits library scope on detail/seasons/episode reads. Added an overload `PlaybackApi.GetWatchDetailAsync(contentId,int? libraryId,int? fileId=null,ct=default)` while retaining the old `(contentId,ct)` route. Added scoped season/episode/item-episode overloads in `CatalogApi.PlaybackScope.cs`; the root's existing `CatalogApi.Hero.cs` item-detail overload is reused unchanged. The watch response has JSON-ignored preparation scope fields so a provided response from a different library/file cannot silently override requested preparation.

`PlayerService.PlayAsync` now has tail optional `libraryId` and `shuffleId`; `GetOrFetchWatchDetailAsync(contentId,ct=default,libraryId=null,fileId=null)` and `PrefetchWatchDetail(contentId,libraryId=null,fileId=null)` scope the coalesced cache by both IDs and existing authority. Identical requests share the same in-flight task; scoped and unscoped requests for the same content do not collide. Next/previous episode lookup, audiobook presentation and multipart transitions preserve the active library hint. Decoder/session recovery, progress, signed-stream handling, subtitle selection, native first-frame loading and existing OSD behavior are retained.

[EbookReader.tsx](https://github.com/Silo-Server/silo-server/blob/22e3a0ba7c1431dda77b957ed1012508d23f2b80/web/src/pages/EbookReader.tsx) retains the library hint when switching file and leaving/continuing manga. Its current catalog calls are unscoped; native uses the supported scoped detail reads to keep file selection within the authorized library versions. Added the tail `LibraryId` field to `EbookReaderNavigation(ContentId,FileId=null,LibraryId=null)`; reader detail/manga detail reads, owning-series Back and next-chapter routes preserve it. Binary reads stay at the existing authenticated `/api/v2/ebooks/{content}/files/{file}/read`; no unsupported library query is added. Explicit supported-file choice, EPUB-first fallback, WebView security, CFI/progress/bookmarks/settings/TOC and previously accepted PDF renderer behavior are preserved.
