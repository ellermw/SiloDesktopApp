## Exact contracts and bounded implementation order

This order is proposed from the public pinned-to-latest diff, not implementation or acceptance. Keep the Oct1 finite acceptance gates separate.

1. **F04 metadata scope:** first prove the current callers reuse metadata under text/rule refinements and reread on library/type/collection/person/technical scope changes. Current `CatalogApi.GetFiltersAsync` already excludes its `q` parameter from the HTTP URL; Library also retains `_filtersTask`. Those are partial source evidence, not proof of all caller cache identities. Add only missing scope/context behavior after a failing acceptance case.
2. **F03 page contract:** preserve `page.next_cursor` alongside `window_cursor`, then choose continuation only from a complete adjacent successful idle uninvalidated page whose snapshot equals the current root window. With that cursor the request omits `seek`; missing, incomplete, refreshing, invalidated or distant boundaries seek directly without loading intermediate pages. Include `explicit_sort` in identity so a server/default sort and an explicit identical sort cannot share an incompatible window. Current desktop `CatalogResponse.Page` already preserves nested `next_cursor` via `BrowsePage`; the callers do not yet select it; `GetCatalogAsync` always adds seek. Coordinate API/window ownership with root before modifying shared paging.
3. **F02 capability and editor preservation:** fetch `GET /api/v2/capabilities/ratings`; available state supplies `sources[].source`, other states and initial loading supply an empty set. The newly conditional sort options are specifically `rating_rt_critic` and `rating_rt_audience`; IMDb/TMDB sorts are not tagged as conditional in `querySortOptions.ts`. An editor's saved field bypasses only the hidden-provider test, while scope/personalized applicability still applies. Ordinary catalog normalization has no keep-field override. Prove one hidden ordinary sort, a saved hidden editor sort, and a scope change before broadening to other caller controls.
4. **F01 display rating:** preserve detail `ratings[]`, and use finite `0 < score <= 10` IMDb before valid TMDB for the hero's one primary rating. Round positive decimal halves through `Math.round(value * 10) / 10` before one-decimal formatting (7.35 → 7.4), rather than relying on binary `toFixed` behavior. Small hero entries use provider/score gap6, a 12px semibold75%-opacity text provider mark, a 14px bold tabular score; TMDB instead uses the official SVG at height8. Invalid/no scores omit the entry. Coordinate common rating/data/icon ownership with root/media; do not use a generic star or invented provider logo.
5. **F05 account authority:** the actual wire signal is `access_changed` and its closing code4001. Whichever arrives first handles the change once per socket: invalidate access-dependent surfaces, refresh the account record, and reconnect immediately for a new ticket. A reconnect also refreshes the account because access may have changed while disconnected. This is broader than merely listening for separate role/permission application event names. Root owns event-channel/account authority; the browse acceptance case should verify an authoritative reread and rejection of an old in-flight response after that integration.

Each group needs its own failing-before/fixed-after behavior or rendered gate. Source inspection of these contracts does not upgrade the current native acceptance count.
