## Required desktop correction groups

### C1. Preserve server Auto audio intent at initial start

**Proven behavioral mismatch.** Upstream [e7605afe / #3115](https://github.com/Silo-Server/silo-server/commit/e7605afe282ba17ec82fd909fff5242799b480b5) refines an automatic preference to another main track of the same language when the chosen track needs conversion and another track plays unconverted with at least the delivered channel count. Commentary/audio-description substitutions are excluded; ties prefer channels, Atmos and codec quality. An actual saved series signature/index remains authoritative. The handler only enables this when the request supplies neither audio track ID nor index, and re-evaluates the original preference on the lower version selected by buffered Auto. See [start selection and lower-version refinement](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/api/handlers/playback_v3.go#L1963), [saved preference detection](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/playback/audio_select_v3.go#L36), and [candidate rules](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/playback/audio_select_v3.go#L47).

Desktop `src/SiloPlayer/Services/PlayerService.cs:2050` calculates `audioTrackIndex ?? bestVersion.EffectiveAudioTrackIndex`, passing the result on both the ordinary start and one-stream-limit retry. `src/SiloPlayer.Core/Services/PlaybackManager.cs:167` serializes that as explicit `audio_track_index`. Catalog effective preference is therefore promoted to a new explicit request even when the viewer chose Auto. This bypasses the new server refinement. Broad libmpv codec support means many ordinary direct plays correctly stay unchanged, but conversion/container/output cases and lower-version Auto starts do not receive the new behavior.

Required implementation invariants:

- A new item start sends an audio index only for an actual explicit preplay/caller choice. A normal Auto start omits the property; the server loads remembered series preferences itself. Do not replace absence with zero or the catalog effective index.
- An explicit viewer choice survives the one-stream-limit retry, later local changes, track/quality replans, manual version switches and recovery. Keep existing signature/language mapping across reordered inventories.
- An automatically granted plan track is applied from the **accepted** `effective_media_file_id` and `selected_tracks.audio.index`. Never apply the requested file's ordinal to the lower source. Existing `PlaybackManager.cs:310` and `PlayerService.cs:2081` adopt these accepted values and should remain authoritative.
- Distinguish a fresh Auto start from transport/session replacement. `PlaybackManager.TrackIntent.cs:137` deliberately captures a granted track when replacing a session; removing that behavior globally would regress recovery continuity. Explicit user selection and saved series preference must not be erased to make Auto work.
- Do not save a server capability fallback as a new profile/series audio preference. Existing `PrePlayAudioSelection` persists only user actions; preserve its Auto-delete, rollback and ownership behavior.

Focused existing tests to extend: `tests/SiloPlayer.Tests/PlaybackManagerTests.cs`, `PlaybackTrackIntentTests.cs`, `CurrentPlaybackQualityTests.cs`, `PrePlayAudioSelectionTests.cs`, and the existing native `Oct24TrackChoicesNativeFixture`. A manager-only start test is insufficient because the unwanted default originates in `PlayerService.PlayCoreAsync`; add a real call-path/native fixture or a shared start-intent policy exercised by that path. Assert omitted Auto JSON, explicit index retained on retry, remembered preference left for server resolution, accepted alternate source index applied, manual reordered mapping preserved, and no automatic preference write. Upstream's concrete lower-version regression is [TestBufferedAutoRefinesAudioOnTheLowerVersion](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/api/handlers/playback_connection_test.go#L282): requested TrueHD/E-AC-3 ordinal 1 must not become the lower file's unrelated stereo AAC ordinal 1.

### C2. Close transport-error logging's signed credential gap

**Proven logging mismatch.** Upstream [ff448b49 / #3137](https://github.com/Silo-Server/silo-server/commit/ff448b49f27aee6fc2f4307f60a6aff4b3396d65) and [95640bd2 / #3126](https://github.com/Silo-Server/silo-server/commit/95640bd259bac054e007b7dd54babc74cac1f11c) scrub signed token paths and raw HTTP errors. The new server sanitizer recognizes percent-decoded JWT-shaped path segments, covering `/stream/direct|remux|transcode/<token>/...` and `/downloads/file/<token>`; it also sanitizes wrapped HTTP URL errors. See [shared URL sanitizer](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/logredact/url.go#L14).

Desktop intentionally formatted stream URLs already use `PlaybackUrlRedactor`, which removes all queries and known stream-path credentials. However `src/SiloPlayer/Services/HlsProxy.cs:299` and `:305` log raw HTTP exception messages; `src/SiloPlayer.Core/Services/DirectStreamRelay.cs:283` does likewise. Their default sinks reach `LocalLog.AppendLine`, whose `RedactSensitiveData` at `LocalLog.cs:135` only replaces known bearer/query/JSON names. Its query list at `:196` omits `st` and `dt`; it does not scrub signed path segments or `/downloads/file/<token>`. A transport exception containing its requested signed URL can therefore bypass the dedicated URL redactor. This is a source-proven failure path; no real credential was read or logged in this audit.

Required implementation invariants:

- Transport failures containing relative or absolute URLs, signed path segments, token query parameters, encoded JWT path characters and nested/wrapped HTTP errors must not persist credentials.
- Apply a common safe sanitizer to raw diagnostic/error text; do not depend on every caller remembering the separate URL-only formatter. `LocalLog.RedactDiagnosticText` already drops complete absolute HTTP URLs and can be reused where appropriate; it currently does not cover relative signed URLs generally.
- Keep useful status/error type/operation information. Preserve the existing exception-chain bound and log rotation.
- Cover stream and download paths and all current API versions. The synthetic test tokens need no real account or network.

Focused existing tests: `tests/SiloPlayer.Tests/LocalLogTests.cs`, `PlaybackUrlRedactorTests.cs`, `DirectStreamProxyTests.cs`, and the HLS proxy tests/source fixture. Verify the actual log sink after a synthetic URL-bearing transport exception, not only a helper return. Include percent-encoded path segments, `st`, `dt`, known `token`/Authorization redaction, normal nonsecret paths, and punctuation after a URL. No need to print a real token to validate this.

### Related media authentication boundary: retain existing protection; harden subtitle helper

Upstream [1ede9b33 / #3131](https://github.com/Silo-Server/silo-server/commit/1ede9b33ecad9ac5347d6d0144b7e95c9a5fcc23) stops appending the login token to **absolute** distributed URLs; only API-relative delivery paths receive it. Desktop main-stream handling is already substantially aligned: `PlaybackDeliveryUrl.cs:8` preserves absolute signed URL bytes; `DirectStreamProxy.cs:45` withholds bearer authentication for known signed node routes; `HlsProxy.cs:64` and `:461` restrict refreshed query authentication to the original integrated origin and exclude known signed node paths. Existing `DirectStreamProxyTests.SignedNodeUrl_PreservesSignedQueryAndNeverSendsBearerToken` explicitly asserts this.

An uncovered helper remains: `PlaybackManager.cs:834` resolves every subtitle URL and then unconditionally calls `UrlHelper.AppendToken`; `src/SiloPlayer.Core/Helpers/UrlHelper.cs:9` appends the account token to any URL. An absolute signed subtitle resource would receive the account token. Current v3 subtitle inventory builders inspected here generate API-relative URLs ([subtitle_inventory_v3.go:303](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/playback/subtitle_inventory_v3.go#L303)), so this is a **proven unsafe boundary helper and verification gap**, not a demonstrated ordinary current-plan disclosure. Proxy subtitle routes exist separately as `/stream/subtitles/{token}/{track}` ([proxy/server.go:300](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/proxy/server.go#L300)); current `IsSignedNodeUrl` helpers only recognize direct/remux/transcode.

For alignment, authenticate based on the original API-relative resource/origin, preserving an absolute distributed subtitle URL and signed bytes. Test relative integrated subtitle authorization, absolute signed URL unchanged, cross-origin child playlists, and token refresh. Do not merely suppress authentication for every resolved absolute URI: all integrated resources become absolute after resolution. Do not rewrite signed stream semantics or add seek/query fields to protocol-v3 URLs.

Review refinement: native integrated absolute URLs on the configured origin/deployment prefix still require account/viewer authentication, including with `st`; see [playback_delivery.go:69](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/apiv2/playback_delivery.go#L69) and [route authentication:105](https://github.com/Silo-Server/silo-server/blob/564b906b8eb529c77c5e0b5c640aa13c1133c7f1/internal/apiv2/playback_delivery.go#L105). The WebUI's absolute distributed-URL rule must not become a blanket exemption for native same-origin `/api/v2/stream/{session}/subtitles/{track}` URLs. Final implementation tests must cover both forms separately.

## Structural contract check and verification limits

Compared the parsed committed OpenAPI objects at both exact commits. Existing schema changes outside the companion UI scope are `DeliveryCapabilityV3.max_channels_by_codec`, `EffectiveRecipeV3.segment_container`, `SystemInfo.request_origin`, `SectionOverrideWrite.item_limit.maximum=500` and a marker-provider sharing description. The auth/session/download protections above do **not** silently rename login/token/download fields. This structural comparison is not a complete semantic/client-contract test: route aliases, signed bytes, retry behavior, error mapping and in-flight profile ownership require behavioral coverage.

No fresh tests ran in this delegated audit. Required release validation remains with parent: source/contract tests for C1/C2 and boundary helpers, complete official native-v2 route verification, exact-payload native player checks, published-service playback checks, no source/payload drift, and visual verification for any UI changes. Do not claim complete API parity, actual phone/LDAP/provider interoperability, physical Dolby Vision/HDR transport, or a root cause/fix for historic direct-play buffering from these findings.
