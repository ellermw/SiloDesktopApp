## Wire, safety and bounds

- `AdminStorageApi` is a separate domain API on the bounded admin transport: captured admin lease, deadline including the body (reads 15 s, source-health probe 30 s, commands 30 s), 256 KiB bound on success and problem bodies, no authentication replay and no retry. It reads only `artwork_storage` from server status (missing `status_known` = unknown), capabilities (`state`, `allowed`), source health (bounded, redacted text; progress clamped 0–100) and the newest `storage_transition` job (`limit=1`; a larger page or another kind is invalid). Job states map as the official adapter (`succeeded`→completed, `canceled`→cancelled, `canceling`→running); free-form failure text is never retained.
- `POST /admin/storage-transitions` sends the policy and the reviewed values once. Policy and key set are validated before sending. 202 must name a `storage_transition` job; 408/5xx, transport failure or an unusable acknowledgement is an **unknown outcome**: the review closes, the draft stays, jobs and status are re-read, and nothing is resent (the server also rejects a second active transition). Known rejections keep the review open with the official failure toast. Cancel targets exactly the captured active job, requires its acknowledgement, dedupes activation and treats ambiguity the same way.
- Settings use the shared `AdminServerSettingsApi`/`AdminServerSettingsStore`/`AdminSettingsForm`: exact strong ETag If-Match, no 412 replay (explicit Reload), unknown save outcomes never replayed, environment-managed keys excluded, credentials never read back, erased after acknowledgement, never echoed (S3 check replies redact submitted access/secret values) and never logged. The connection check sends only staged credentials; any edit to that group hides its result.
- `AdminStorageSettingsController` owns an `AdminAuthorityLifetime`: every read/command runs under an action lease of the current owner; late results for a retired owner are dropped; retirement clears the draft, review, results and polls.
- **Polling only while the page and its window are active:** recovery source health every 5 s only while `recovery_pending`; jobs every 2 s only while the newest transition is queued or running (official `useAdminTaskJobs(…, poll)`). Reads coalesce per kind; background ticks yield while playback is loading. Activation refreshes jobs/recovery, status after 15 s and capabilities after 60 s (official stale times).

## Native differences and limits

- No live S3/migration, installer, physical-input, every-DPI, Narrator, IME or comprehensive WebUI visual verification is claimed. Synthetic native captures were inspected; they are not a live-server comparison.
- English text only, copied verbatim from official `en.json` at `8f93594c` (155 `web.admin.settings.storage.*` keys) plus two native unknown-outcome messages; no other locale.
- The source-health probe is not refetched on window activation (the WebUI would); Retry check is explicit, to avoid unrequested S3 probes.
- Only the newest job is requested (`limit=1`) since only `data[0]` is shown.
- The storage attention dot in the sidebar (restart pending) is not implemented in this leaf.
- Preflight details in the 202 body are not displayed (the WebUI does not show them either); `Retry-After` is not used.
- The Advanced disclosure choice persists through the existing `LoggingDisclosurePreferences` (`storage.s3.public`), as Downloads does.
- Full-page credential/lock-status alerts add a Reload action.
