### A. Password change: optional sign-out of other devices

**Confirmed missing opt-in behavior.** Upstream `changePassword` accepts `sign_out_other_sessions` and advertises support through the password capability. The WebUI shows an initially unticked checkbox only when advertised. A server that omits the capability rejects this member, so sending even `false` universally is not compatible. When selected, the current sign-in remains valid, other compatible sessions are revoked, and API keys remain. [Capability and command](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/internal/apiv2/account.go#L43), [WebUI form](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/pages/settings/AccountSettings.tsx#L51).

Desktop `AccountPasswordCapability.cs:3`, `AccountPasswordApi.cs:14`, `AccountPasswordViewModel.cs:17,97`, `SettingsPage.AccountPassword.cs:20` have no capability member, selection or request member. Add the capability-gated unchecked option, omit the request member unless explicitly selected and supported, and preserve the existing page/profile generation, cancellation and credential-clearing gates. Test old/new capability bodies, absent/selected request shapes, page/account departure and in-flight submission. This is a self-contained Beta PR.

### C. Match/Split library scope and stale candidate ownership

**Concrete reachable mismatch, requiring curated-item UI tests.** The current WebUI passes the item's current library into Match and Split. If an unscoped admin view names several libraries, it asks the user to select one from the item's file inventory. Split can infer a single shared library from the selected files. Results from a previous library cannot later be applied after a split or scope change. [Upstream correction and rationale](https://github.com/Silo-Server/silo-server/commit/cb73e114bd09ba0bc748a156f0f129b4bd12822e), [Match](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/components/MatchItemDialog.tsx#L93), [Split](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/components/SplitItemDialog.tsx#L68).

Fix the complete search → result → apply/preview/commit ownership sequence, not just the constructor argument. Preserve curator authorization and captured context; do not expand admin access. Tests need scoped and unscoped multi-library items, selected-file inference, library membership changing while open and delayed candidates from a retired scope. Separate PR from event coherence.

### E. Home row payload reduction with complete-row recovery

**Confirmed optional performance opportunity, not an immediate compatibility break.** Upstream can cap rows to 20 cards initially and expand a partial row near its end. `/home/capabilities` distinguishes `row_item_limit_max` (individual rows/layout includes) from `section_item_limit_max` (aggregate section reads). Old servers reject unadvertised `item_limit`. `has_more`, exact total, already-expanded cache state and cross-row dedupe determine whether an uncapped completion read is needed. [API caps](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/internal/apiv2/home.go#L108), [response](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/internal/apiv2/library_views.go#L82), [WebUI policy](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/hooks/queries/homeRowLimit.ts#L9), [row completion callback](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/components/SectionRow.tsx#L107).

Desktop `HomeApi.cs:11,25` always requests uncapped layout/rows. `HomeSectionWithItems` has no `HasMore`. `HomeViewModel.cs:513,576,605` owns fetching/reconciliation. Implement the whole capped → near-end → uncapped completion lifecycle and preserve cached expanded rows and dismissal reconciliation. Merely appending `item_limit=20` would truncate reachable cards. This warrants a separate performance PR and exact row/card behavior tests, not a quick API-only edit.

## Requested alphabet navigation: authoritative contract

The alphabet feature exists in the pinned official source; it is not inferred from first letters of downloaded desktop cards. `POST /api/v2/catalog/letters` accepts the same query scope/rule groups as catalog query browsing, with `library_id`, `type`, `match`, `groups` and title `order`. It returns exact `total`, each available letter's `count` and zero-based first `position`, and `runs` for the current-letter indicator. Use `position` as catalog `seek`, with the same filters/title order; do not download every preceding page or turn a letter click into a permanent prefix filter. [API](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/internal/apiv2/catalog_letters.go#L25), [capability](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/internal/apiv2/catalog_search_capabilities.go#L19), [query hook](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/hooks/queries/catalog.ts#L606).

WebUI behavior to retain:

- Display the right-side `# A…Z` rail for ungrouped title-sorted Library browsing with no query limit. Hide it for non-title sort, grouped audiobook axes, empty results and an unsupported/failed initial index. Default query-source browsing has no free-text `q`. Both ascending and descending title order are supported.
- The server uses sort title (e.g. “The Hobbit” filed as “Hobbit, The”), folds accented Latin initials, and puts digits, symbols and non-Latin initials under `#`. Use server positions; `runs` can repeat a letter because database collation may separate accented titles.
- Hold the rail's width while loading, with disabled letters. Disable unavailable letters; show available letter counts through accessibility. Active letter follows the end of the visible top row. A final-letter jump can retain its selected highlight at the bottom until the user scrolls away.
- Roving keyboard focus: one tab stop, arrows/Home/End/typed initial to move, Enter/Space to jump. Touch scrubbing jumps through available letters. At short heights WebUI wraps the 27 entries into two columns; desktop must keep them reachable without clipping.
- Keep index/results bound to the same account/profile/query generation, invalidate on filters/order/library refresh, and retire pending jumps after navigation. Index and page reads are not one snapshot; use at least the larger of the index total and already-known results so concurrent scans do not hide returned cards.

Primary UI sources: [Library gating/count/scroll state](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/pages/LibraryBrowse.tsx#L208), [jump integration](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/pages/LibraryBrowse.tsx#L417), [rail input/layout](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/components/catalog/LetterBar.tsx#L21), [run lookup](https://github.com/Silo-Server/silo-server/blob/63ef34b236b88dc77acca1a9a3ed90235377691f/web/src/components/catalog/letterIndex.ts#L15).

Desktop's existing `LibraryViewModel` virtual catalog already has scoped page/window loading, query versions and seek; build on those seams. Preserve signed window page-size scope, stale-cursor recovery, item count estimation and navigation restoration. Add letter request/response and capability support to `CatalogApi`, and a separately owned index/jump lifecycle to LibraryPage/ViewModel. Native tests should demonstrate a letter beyond the first page, filtered and descending jumps, sort-title/accent/# cases, unavailable letters, narrow/short layouts and late old-profile/index/page callbacks.
