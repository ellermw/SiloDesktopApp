Android supplies useful precedent for preserving a direct stream through recoverable transport failures. It does not prove that Windows' current stall has the same cause, and Android can still request a server replan after recovery is exhausted.

1. **The native video path loads the issued URL through Media3 HTTP data sources.** `SiloPlayerFactory` resolves the URL and gives it to `MediaItem.setUri`; the routed data source opens HTTP directly (or local file/content for offline media). The inspected native path does not insert a loopback relay. Absolute URLs are retained; this does not mean every server-issued URL is signed. Only `ORIGINAL_HTTP` activates the original-file resume guard. Phone and TV use Android shared playback code; this is Media3/OkHttp behavior, not libmpv behavior. [MediaItem and original delivery](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/SiloPlayerFactory.kt#L492-L505), [URL resolution](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/SiloPlayerFactory.kt#L749-L759), [HTTP dispatch](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/AuthenticatedDataSourceFactory.kt#L296-L309).

2. **Two recovery layers preserve transport before replanning.** The shared load policy retries timeouts/socket/connect/DNS failures and selected HTTP errors; original-file HTTP/2 resets, connection shutdown, and EOF exceptions require byte progress in the failed attempt. `ProtocolException` with “unexpected end of stream” has a separate retry branch without that original-file/progress restriction. Entity changes are rejected, and parser failures are rejected after the earlier network checks. The policy uses 1/2/4/8-second backoff (or numeric Retry-After), bounded by a 90-second retry budget including measured elapsed time. This lets Media3 resume extraction at its byte position without first surfacing a player error. `If-Range` uses a previously observed strong ETag; changed entities during a ranged reopen fail explicitly. [Policy implementation](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/MediaLoadRetryPolicy.kt#L53-L81), [failure eligibility](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/MediaLoadRetryPolicy.kt#L154-L256), [budget/backoff](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/MediaLoadRetryPolicy.kt#L258-L286), [entity guard](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/AuthenticatedDataSourceFactory.kt#L156-L196).

   Above that, both phone and TV recognize `ERROR_CODE_IO_NETWORK_CONNECTION_FAILED` and `ERROR_CODE_IO_NETWORK_CONNECTION_TIMEOUT` and allow one same-plan remount at the current source position mapped into the player timeline. A `transport_stall` preflight event has a similar reopen path. It requires an active plan and successful `recordTransportReopen()`, which refuses a duplicate `transport_reopen` mutation for the current attempt. Therefore a reset of the view model's retry counter alone does not imply unlimited reopen eligibility. TV additionally increments a transport mount nonce. If these conditions fail, a pending seek enters seek recovery; other session errors enter protocol-v3 replan. [Phone runtime handling](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/androidApp/src/androidMain/kotlin/org/siloserver/silo/android/ui/screens/player/PlayerViewModel.kt#L1612-L1665), [phone stall handling](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/androidApp/src/androidMain/kotlin/org/siloserver/silo/android/ui/screens/player/PlayerViewModel.kt#L1475-L1505), [TV runtime handling](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/androidTvApp/src/androidMain/kotlin/org/siloserver/silo/tv/ui/screens/player/TvPlayerViewModel.kt#L5345-L5402), [attempt guard](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/PlaybackSessionManager.kt#L2481-L2484).

3. **Decoder failures are distinct evidence.** The phone implementation maps decoding/init/unsupported-format errors to `decoder_failure`, network connection/timeouts to `transport_stall`, bad HTTP status to `http_failure`, missing source to `source_unavailable`, and other errors to `player_failure`. Its replan call includes classification and error diagnostics. This is the most useful comparison for Windows' generic `decoder_or_transport_error`: an interrupted HTTP response is not automatically evidence that the codec/container cannot be played directly. The actual server-selected replacement route cannot be inferred from Android client code alone. [Classification](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/androidApp/src/androidMain/kotlin/org/siloserver/silo/android/ui/screens/player/PlayerViewModel.kt#L2006-L2018), [replan dispatch](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/androidApp/src/androidMain/kotlin/org/siloserver/silo/android/ui/screens/player/PlayerViewModel.kt#L1645-L1665).

4. **Buffering deliberately limits how long reading can stop.** Shared policy fixes maximum-minus-minimum buffer duration at 15 seconds of media time; comments explain the old 50/120-second pair let upstream connections sit idle for 70 seconds. The 15-second interval remains 30 seconds at the supported 0.5x rate, below an assumed 60-second proxy timeout. Target depth is 180 seconds, startup 2 seconds, rebuffer 5 seconds; `SiloLoadControl` sizes actual depth/bytes using stream bitrate and device memory, so 180 seconds is not guaranteed. These constants are Android's proxy assumption, not measured production timeout evidence. The pooled transport sets 20-second connect and 30-second read/write timeouts and supports HTTP/2 plus HTTP/1.1. [Buffer policy](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/PlaybackBufferPolicy.kt#L23-L98), [actual sizing](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/SiloLoadControl.kt#L45-L85), [HTTP settings](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/PlayerOkHttpClient.kt#L26-L54).

5. **Auth and heartbeat recovery are separate from codec recovery.** Each media open reads current credentials and retries one same-origin 401 after shared refresh. Explicit plan headers override session headers, and session credentials are added only for the server's origin; this accommodates stream-scoped signed authorization without replacing it. The progress reporter sends the latest position and pause state every 10 seconds while active. A network/gateway failure enters outage recovery; successful decoded health response restores the same session. Health polling has 1-to-8-second backoff and a nominal 90-second accumulated-delay budget (probe duration is not counted by that loop). A missing session has a separate owner-driven renewal path. [Open/refresh](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/AuthenticatedDataSourceFactory.kt#L83-L110), [credential precedence and scoping](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/AuthenticatedDataSourceFactory.kt#L199-L267), [progress](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/PlaybackSessionLifecycle.kt#L703-L745), [outage recovery](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/PlaybackSessionLifecycle.kt#L811-L872), [interval constants](https://github.com/Silo-Server/silo-android/blob/cd1af1a9946b8d6a69c721069c33f222b4aee857/android-shared/src/androidMain/kotlin/org/siloserver/silo/common/player/PlaybackSessionLifecycle.kt#L944-L950).
