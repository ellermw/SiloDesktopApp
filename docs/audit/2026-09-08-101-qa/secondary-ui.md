# Secondary UI audit — .101 preview working tree

Read-only source audit of auth/onboarding/profile pages, secondary browsing tools, settings/account UI, watch parties, and seven supporting services. This is a **source review, not a verified visual-parity or runtime certification**. No application, production service, or source file was changed; no test suite was rerun. The live dirty working tree is the baseline, not a release tag. No current WebUI comparison was performed by this subagent.

Coverage is recorded per file in `secondary-ui-coverage.json`. All 62 assigned implementation files were read in full, including all Settings rendering/event bodies, ThemeService palette definitions, and all 19 XAML documents. The final 323 Settings XAML lines and ten complete auth/onboarding/download XAML files were read by the collaborating backend reviewer; details are in `secondary-ui-xaml-supplement.md`. Fourteen focused test files were read (the 13-file reconciled secondary test inventory plus EbookReaderWebPolicyTests); no suite was rerun. See `secondary-ui-tests.md` and `secondary-ui-tests-coverage.json`. This completes the assigned source-reading scope, not rendered visual parity, runtime behavior, or complete server/API verification.

## Recommendation

Keep WinUI, the native player integration boundary, API models, and successful explicit ownership/cancellation patterns. A wholesale app rewrite would discard useful behavior without fixing the underlying problems. Replace the Settings monolith's orchestration, the watch-party socket transport, and the ebook document/reader lifecycle with small independently testable modules. Change most individual pages incrementally.

The recurring failure pattern is asynchronous work tied to mutable page/service fields rather than the account/profile/server/entity that started it. Read-side generation gates are inconsistent; write-side ordering and stale-result checks are weaker still. A UI can look complete and pass existing source-text parity tests while authenticating after navigation, saving one scope's configuration into another scope, or silently dropping transport actions.

## Concrete findings

Priorities: P1 = potentially wrong identity/data/security state; P2 = normal workflow failure or significant availability concern; P3 = maintainability/UX weakness. Severity marked conditional requires the stated route/runtime condition to establish reachability.

### Authentication and onboarding

1. **P2 — successful profile PIN is reported as failure and its dialog remains open.** `ViewModels/ProfileSelectViewModel.cs:108–145` activates the selected profile on a valid PIN, but never clears `IsPinRequired`; only CancelPin clears it at148–154. `Views/ProfileSelectPage.xaml.cs:150–161` hides the dialog only when that flag is false, otherwise presents failure and clears the input. Newly created protected-profile activation has the same check at197–212. Return an explicit verification result and commit/close the modal before navigation; test valid PIN, invalid PIN, cancel during verification, and newly created protected profiles.

2. **P1 conditional — phone sign-in fails to preserve the originating server/session across await.** `LoginViewModel.cs:230–251` validates the session only at the start of the loop; after `DevicePollAsync` it reads the *current* configured server at241 and passes that as the expected server for returned tokens242–246. Cancellation/session identity is not rechecked after the response. A completion racing cancel/server-switch can commit tokens from the old operation under the new server. Capture server/auth generation before starting the phone flow and verify both after every await. OAuth and signup already capture server before their network call; reuse that design.

3. **P2 — auth completion can navigate after leaving login/signup.** `LoginPage.xaml.cs:22` subscribes to success and `OnNavigatedFrom:47–51` cancels only phone login, without unsubscribing or canceling credential sign-in; `OnLoginSucceeded:53–57` navigates unconditionally. `LoginViewModel.cs:368–370` has no page lifetime token. Signup similarly subscribes at `SignupPage.xaml.cs:20`, never detaches, and navigates at47–58 after uncancelled signup/profile discovery (`SignupViewModel.cs:173–200`). Navigate Back while a delayed login completes to reproduce stale navigation. Retain immutable authentication ownership even where account creation itself cannot be rolled back; suppress stale UI completion.

4. **P2 — invite loading uses replaceable cancellation/navigation fields after await.** `InviteClaimViewModel.cs:31–63` replaces `_lifetime` but writes Invitation/error/loading without owner guards; its cancellation filter dereferences the mutable field after Cancel nulls it. `AcceptAsync:98–110` uses mutable `_navigation` again after accepting. A retried/new invite can be overwritten by an older response or receive its account-state completion. Capture navigation and CTS locals, validate generation, and clear passwords on completion/navigation.

5. **P2 — taste picker completion can navigate after cancellation.** Load and pagination have good owner gates (`TasteSeedViewModel.cs:46–123`), but Submit143 has no lifetime; `TasteSeedPage.xaml.cs:48–56` always remembers dismissal and navigates after success, even after Cancel42–46. Disable competing navigation while the decision is pending or let navigation invalidate UI ownership. Do not mark the newly selected profile dismissed from an old operation.

6. **P2/P3 — tour writes/navigation are not serialized.** `Dialogs/FeatureTourDialog.cs:148–163` disables only one radio, allowing whole-setting requests to overlap and complete out of order. Primary216–233 increments `_index` before awaiting report without a deferral/busy guard; Back/Skip or another Next can change the index while reporting. Defaults displayed at133–144 are not saved unless clicked; returning to a choice reconstructs the default rather than the user's prior choice. Preserve per-step draft values, serialize commits, guard navigation, and explicitly define whether an accepted default is persisted. External links113–116 accept any absolute scheme and have uncaught launcher exceptions; constrain to supported web links and surface failures.

7. **P2 — avatar picker reads arbitrary-sized files fully and lets failures escape an async UI handler.** `ProfileEditorDialog.cs:347` awaits PickAvatarAsync with no catch; picker/read/preview at513–534 has no byte/dimension budget or cancellation. File access failure or oversized images become an unhandled UI exception/memory spike. Add a bounded decode/read boundary and inline errors. Save blocks dialog close/primary only134,546, while other controls remain mutable; avatar upload uses fields after profile-save await571–579, so the uploaded image may differ from the profile snapshot submitted. Snapshot the whole draft and lock the form for save.

8. **P3 — profile editor accessibility and maintainability.** Avatar image buttons489–509 have no accessible names; `Field:739–744` and toggle rows754–772 display adjacent labels without explicit `LabeledBy`/names. Do not infer that every control is inaccessible; inspect with UI Automation/Narrator. Fixed six-column avatar/180px identity layout needs 200% text and narrow-window verification. Keep API-backed access restrictions, explicit PIN validation, upload capability gating, and separate partial-avatar-failure feedback.

### Settings and account integrity

9. **P2 — settings load has nondeterministic precedence.** `SettingsViewModel.cs:450–550` defines legacy next-up/autoplay loads and typed effective playback loads that assign the same properties; `Task.WhenAll:559–570` launches them together. Whichever finishes last wins, so a slow legacy preference can override an effective profile-device setting. Theme/accessibility/custom-theme application is similarly interleaved. Resolve the final effective snapshot in a deterministic precedence order, then publish it once.

10. **P1 — home section scope can change while old rows are loading, then save into the wrong scope.** `SettingsPage.xaml.cs:2501–2505` changes SelectedScope before executing LoadHomeSections. `SettingsViewModel.cs:1478–1500` drops the second request when already loading, then publishes the first scope's rows. `SaveHomeSections:1517` / save helper1570 chooses the now-current scope. Capture scope per draft; changing it must cancel or supersede the previous load and disable mutations until matching data is loaded. Regression test: delayed Home response, select library, toggle/reorder section.

11. **P1 — webhook detail races can save another connection's users into the selected connection.** `SettingsPage.xaml.cs:5471–5516` sets `_selectedWebhookConnection` synchronously, then unconditionally renders response actors/events after await. Select A then B with A slower: A's selectors overwrite B's detail. SaveActors6031–6040 sends selectors to *current B*. Similarly Rotate5997–5999 requests A then stores its returned URL on mutable current B. Bind an immutable connection ID and generation to both draft and mutation; only matching responses may update UI.

12. **P2 — device detail requests overwrite newer selection.** `SettingsPage.Account.cs:148–151,239–345` can start overlapping detail fetches on the same content host; no generation or selected-device comparison exists after capabilities/effective settings awaits. Fast A→B can display A while B is selected, and handlers close over A (`654–754`). The scope list (`169–207`) also lacks latest-request ownership. Add per-scope/device load generations and stable selection-based drafts.

13. **P2 — rapid settings changes can persist stale documents.** LibraryCardViewModel's property callbacks fire-and-forget whole-preference saves (`SettingsViewModel.cs:148–175`); library visibility693–723 and order750–765 similarly persist whole lists with no queue. Older saves can win; reorder rollback uses stale indices after another move. Theme overrides `ThemeService.cs:873–920` fire-and-forget whole dictionaries and swallow failure. Notification preferences and ebook appearances repeat this pattern. Use per-profile/per-key serialized latest-value queues, with acknowledged snapshot distinct from draft and visible retry errors.

14. **P2 — partially failed profile-setting save is called successful while old device override stays effective.** `SettingsViewModel.cs:866–894` writes a profile value then swallows failure deleting the profile-device override871–872. AutoPlay785 follows the same approach. If deletion fails, current-device playback can still follow its old override although UI says saved. Report partial failure or update the effective snapshot and offer clearing the override; do not claim current behavior changed until it did.

15. **P2 — caches are not consistently scoped/invalidated while operations are in flight.** `UICustomizationService.cs:33` invalidates only `_loaded`, while an in-flight refresh publishes values74–91 and may mark the old profile loaded. Failure reset193 sets loaded true, suppressing subsequent EnsureLoaded retries. `CardOverlayService.cs:291–298` save can publish its old-profile document after Invalidate283–289 because write-side ownership differs from its good read-generation guard270. Capture server/profile generation before all loads/saves, invalidate documents, and apply results only to matching identities.

16. **P2 — appearance debounce loses edits on navigation; overlay debounce can cross navigation.** CSS save is delayed one second (`SettingsPage.xaml.cs:726–766`) and navigation cancels it299–312 without flush/draft warning, losing recent text. Conversely `_overlaySaveCts` is not canceled on navigation;250ms later its save2140–2142 uses current API scope. A profile transition inside the delay can save the old draft under another profile. Scope writes explicitly; implement a deliberate flush or retained draft policy.

17. **P2 — Settings plugin forms initialize before their values exist.** `SettingsViewModel.cs:2089–2112` adds the summary first, triggering `SettingsPage.xaml.cs:4209–4274` to rebuild against absent values. The last plugin does not receive a later collection notification after its dictionary loads; its visible controls stay blank/default. Early edits have no dictionary to update4325/4344/4373. Load summaries+values into a complete snapshot, then render; failed-value loads must not become an editable empty configuration.

18. **P2 conditional — secret plugin fields use plain TextBox.** `SettingsPage.xaml.cs:4352–4362` creates a TextBox and the `field.Secret` branch is empty. A schema with a secret value renders it visibly. PluginsTab is intentionally collapsed (`CurrentSettingsParitySourceTests.cs:358–364`), so this is a retained hidden-surface defect, not an assertion that default Settings presently exposes secrets. Remove this obsolete route if unsupported; otherwise use PasswordBox and explicit reveal semantics before exposing it.

19. **P2 — import Plex sign-in continues polling after page departure.** `SettingsViewModel.cs:1795–1856` loops up to60 with two-second delays1831 and no page cancellation. `SettingsPage.xaml.cs:299–312` cancels the separate *webhook* Plex CTS, not this import flow. Retained Settings VM/page also holds source credentials. Cancel each flow independently and clear transient credentials after use/cancel; retain only deliberate secure persistence.

20. **P2 — saved controls disagree with server on failure.** Device toggle/select/number handlers (`SettingsPage.Account.cs:660–754`) re-enable and toast failures but keep the unsaved visual value. The “changed here” indicator is derived only from initially loaded data799–823, so creating/deleting an override can leave its scope label stale. Use acknowledged effective values and reload after write; revert failed edits. Device detail includes several NumberBoxes using culture-sensitive parsing of server raw JSON714/742; use invariant parsing for numeric JSON.

21. **P3/performance risk — Settings eagerly constructs an unusually large retained visual tree.** `SettingsPage.xaml` has1,104 XML elements and133 interactive nodes, excluding the many generated trees. The page is cache-required (`SettingsPage.xaml.cs:113`); language option builders231 and metadata-exception builders333–387 materialize options repeatedly. Many collection-change listeners rebuild whole cards, such as plugins4209–4232. This is a credible realization/allocation hotspot, **not a measured current freeze**. Replace with lazy section views and virtualized/data-bound rows, preserving contract semantics. Avoid transporting layout in thousands of lines of procedural element construction.

22. **P3 — unavailable forms rely on hit testing instead of disabling.** Settings interface host1292–1331/1371 and overlay host1749 use IsHitTestVisible to suppress interaction. That does not provide a complete keyboard/UI Automation disabled state. Set IsEnabled or gate every command as well; test tab/space actions while capability fetch fails.

23. **P3 — menu draft reset and dirty tracking can mislead.** Reset at1667–1673 refreshes effective menu then replaces the draft with hard-coded defaults, potentially differing from inherited server defaults. Save1652–1665 can clear dirty after additional in-flight edits. Bind dirty to draft-vs-acknowledged equality and render the returned effective result.

24. **P2 — webhook creation includes stale Plex resource fields for another provider.** `SettingsPage.xaml.cs:5421–5444` reads Plex combo selection regardless of selected provider; the body adds server_id/base_url/access_token whenever a Plex item remains selected, even for Emby/Jellyfin. Switching provider after Plex authentication can submit irrelevant credentials/config. Include Plex fields only when provider is Plex, clear irrelevant draft state, and test switching providers after successful sign-in.

### Requests, downloads, notifications

25. **P2 — cancel request is implemented only in an unused renderer.** Active My Requests builds poster cards (`RequestsPage.xaml.cs:169–217,528–644`) with no cancel action. The cancel button exists in BuildRequestRow484–526, but that method is not used; handler700 is consequently unreachable from active cards. Expose allowed cancellation in the rendered card/detail actions and remove the dead renderer. Existing source-string tests can pass merely because the dead Cancel text exists.

26. **P2 — request mutation success is conflated with failed refresh.** `RequestDetailPage.xaml.cs:135–136` submits successfully then fetches detail in the same try; if refresh fails, the catch reports “Request failed” and re-enables submission. Keep acknowledged success state and report a refresh problem distinctly. RequestBrowse/Requests show similar mutable status rebuilding concerns; evaluate duplicate protection on the server, not by assumption.

27. **P2 — Requests My Requests truncates at100 and does not paginate.** `RequestsViewModel.cs:95` requests limit100 and the page presents that collection as the user's list. Accounts over that bound cannot reach older requests here. This is a client-side omission; actual server limits and any intended product cap were not verified. Add paginated state and counts from the response.

28. **P3/performance risk — Requests rebuilds hidden sections for unrelated updates.** `RequestsPage.xaml.cs:139–167` rebuilds search, discovery, brands and personal cards, including hidden sections;169–217 realizes all requests. Search/resize/mutation can trigger repeated remote image/card creation. Use incremental lists and independent section invalidation. RequestBrowse's GridView, bounded cast list and explicit cancel-on-navigation patterns should be kept.

29. **P2 — saving a managed download omits the device identity required to retrieve it, causing 404.** `DownloadsPage.xaml.cs:257–274` uses raw DI HttpClient with only Authorization, whereas `SiloApiClient.AddDeviceHeadersUnsafe:557` includes X-Silo-Device-Id on the list/create API path. The root reviewer verified the freshly fetched official server main `aeb82e1c935336eba7a4a7b22233134dbee13c4c`: [downloads handler](https://github.com/Silo-Server/silo-server/blob/aeb82e1c935336eba7a4a7b22233134dbee13c4c/internal/api/handlers/downloads.go#L450) obtains managed identity; [download service](https://github.com/Silo-Server/silo-server/blob/aeb82e1c935336eba7a4a7b22233134dbee13c4c/internal/downloads/service.go#L922) uses managed access when device is present, but its no-device branch946 rejects a managed download as ErrNotFound. Thus an ordinary managed download listed through the API fails this raw save route. This is cross-repository source-contract verification, not a live endpoint test. Preserve ResponseHeadersRead/stream copying, and route transfers through a scoped service using common device/auth/profile policy. Add progress, cancellation, busy state, destination cleanup and user-visible errors; current failure is Debug-only279 and a transfer can continue invisibly after navigation.

30. **P2 — download filenames assume a container rather than using delivery metadata.** `DownloadsPage.xaml.cs:248–250` chooses .mp4 for transcode, .mkv otherwise. A direct MP4/other file is mislabeled. Use server-provided filename/content-disposition or actual file version metadata. `OpenStreamForWriteAsync:273` has no explicit truncate; verify overwrite behavior with an existing larger destination before assuming it is safe.

31. **P2/P3 — managed download list has no status-refresh lifecycle.** Page load35 loads once; VM31–59 has no polling/event refresh or owner cancellation. Pending preparations remain pending until reentry. It rebuilds all rows60–66 and shows content IDs102 instead of resolved titles. Delete failure is silent (`DownloadsViewModel.cs:63–77`). Keep server DTOs and streaming, replace view-only download orchestration.

32. **P2 — notification mutations are not reliably ordered.** `NotificationsViewModel.cs:246–278` versions response publication but does not serialize server writes; rapid toggles can store an older document last. `NotificationSettingsViewModel.cs:298–307` instead drops any mutation while IsBusy, rather than queuing latest input. The controls reviewer confirmed the form does not disable every relevant input during mutation, so busy-time choices can appear selected without being persisted. Preserve the inbox's good cancellation, pagination, cached-data and rollback patterns; fix writes with immutable drafts and per-profile serialization. Optional channel loads101–110 use all-or-nothing Task.WhenAll, so one optional endpoint failure suppresses other successful channel state.

### Ebook reader

33. **P2 — leaving the reader postpones cancellation and disposal until after network/COM work.** `EbookReaderPage.xaml.cs:120–139` is async void and awaits scroll/progress before canceling lifetime and closing WebView, without a finally/error boundary. Navigation proceeds meanwhile; initialization/render handlers may still access it. Cancel/detach synchronously, snapshot safe progress, dispose deterministically, and save outside UI lifetime with bounded independent ownership.

34. **P2 — many reader actions throw across async-void UI boundaries.** Bookmark603–612, appearance631–653, highlight722–738, annotation deletion757–763, speech829–845 and download949–959 await operations without localized catch. A transient server/COM/file error becomes an unhandled UI exception rather than a recoverable action error. Appearance sliders additionally save the full settings document on every tick with no debounce/serialization. Catch at command boundaries and keep an acknowledged config snapshot.

35. **P2/security availability — ebook extraction has no decompression budget or cancellation.** `EbookPackageExtractor.cs:17–79` checks path containment (keep), but entry copying48/75 is unlimited in expanded bytes/count/ratio and uninterruptible. A malformed/highly compressed ZIP/RAR can exhaust disk/CPU while navigation cancellation cannot stop it. The reader already downloads the complete byte array235 and retains it. Stream with bounded archive budgets, cancellation checks, per-file limits and staged atomic completion.

36. **P2/privacy/cache correctness — extracted book cache is not scoped or evicted.** `EbookReaderPage.xaml.cs:237–238` uses content/file IDs under reader-cache without server/profile identity. Extractor reuses directories and never removes obsolete entries. Two servers with overlapping IDs can leave stale same-path/missing-manifest resources, and books remain on disk after use with no quota/clear affordance. Namespace by server/content version, verify a completion manifest, clear failed/obsolete entries, and bound storage. This is cache identity/retention evidence, not proof a cross-profile document was actually exposed.

37. **P2 — EPUB permits valid package-relative references that extraction rejects.** `EbookPackageExtractor.cs:172` resolves manifest href against packageDirectory, and SafeCombine194–201 requires containment inside that directory. Valid `../Text/chapter.xhtml` inside the extracted book root is rejected. Validate against book root while resolving relative to the manifest directory. Add fixtures for valid sibling directories plus traversal outside book root.

38. **P2 — PDF/comic progress cannot reach expected completion.** `ReadScrollFraction:448–460` only measures HTML; PDF has one chapter and never updates scroll fraction. Comics use chapter index/count while fraction remains0, so last page remains below100%. Next672–681 never commits final fraction1; EndOfBookNext threshold995 may be unreachable for ordinary comic chapter counts. Implement format-specific progress adapters and explicit last-page completion semantics. Test short/long comics and PDF resume.

39. **P2 — comic files sort lexicographically.** Extractor186 orders file paths OrdinalIgnoreCase, so unpadded pages1,10,2 read in the wrong order. Use natural numeric page ordering and metadata order where present.

40. **P2/P3 — ebook search publishes stale results and ignores cancellation during full-book parsing.** `EbookReaderPage.xaml.cs:792–814` reads/parses chapters on a worker, bounded to200 matches but not an owner generation; a later query can be overwritten by earlier completion. Limit work, cancel regex/file processing, and publish only current query results. Keep the reader's explicit WebView navigation, resource, permission, and message-source policy142–181; it is a good boundary to preserve when replacing orchestration.

### Watch parties

41. **P1/P2 — stale room initialization can resurrect a disposed room.** `WatchTogetherRoomPage.xaml.cs:62–72` awaits Initialize then registers the coordinator. Navigation-away93–111 disposes VM/clears coordinator without canceling initialization. The delayed initialization may then register the disposed VM and restore a room the user left. `WatchTogetherViewModels.cs:213–246` has no lifetime or generation for the REST load. Bind room initialization to page/room ownership; never publish after disposal.

42. **P2 — WebSocket sends are concurrent and silently lost.** `WatchTogetherViewModels.cs:455–465` calls ClientWebSocket.SendAsync directly, CancellationToken.None, from several transport/ready/attach paths without a send lock. Concurrent sends are unsupported; errors are swallowed. Replace with one bounded serialized outgoing queue, cancellation, explicit connection epoch, and acknowledged application-level actions.

43. **P2 — session attachment is not restored after early send/reconnection.** Attach353–361 records attached session even when Send returns immediately because socket is not open458. Connect546–604 starts receiving after connect without replaying attachment. `WatchTogetherCoordinator.cs:79,103–106` deduplicates by session, so it will not retry the same attachment. Socket disconnect/reconnect or entering a room with already active playback can leave server unaware of playback. Reconcile desired room/session state on every connection; distinguish desired/acknowledged session IDs.

44. **P2 — room frame size is unbounded.** `WatchTogetherViewModels.cs:574–594` accumulates fragments in MemoryStream without a max frame length, then JSON parsing/publication runs through UI dispatch. A huge server frame can cause memory/UI stalls. Cap message size, parse off dispatcher, and publish bounded immutable snapshot deltas. Keep backoff/nonblocking abort disposal and coordinator receipt/session guards225–262.

45. **P2 — room discovery response races select the wrong candidate context.** `WatchTogetherRoomPage.xaml.cs:475–500` search lacks owner/version/cancellation after debounce; season/episode loads535/564 also have no identity guard. Select multiple series/queries quickly to render old results under newer context. Auto-start acknowledges selection before `_ = player.PlayAsync`207 completes; the surrounding synchronous catch cannot observe async failure, and acknowledged revisions do not retry. Preserve explicit action result and retry state.

### Shared services / host boundaries

46. **P1 conditional — plugin WebView attaches current credentials to a filter for an old server.** `PluginRoutePage.xaml.cs:29–40` creates a resource filter using BaseUrl once but reads current mutable API bearer/profile headers in callback. If an old WebView survives until a server transition, it can send the new server's credentials to the old origin. Page Unloaded closes WebView15, but async initialization28 can race unloading and application transition ordering was not verified in this slice. Parent startup audit must establish reachability. Capture allowed origin+auth scope and check current generation before attaching credentials; block unauthorized navigation/resources. Keep normalized/escaped plugin route segments65–76. Native theme is ignored by hard-coded `?theme=dark`54.

47. **P2 — high contrast applies white foreground to light backgrounds.** `AccessibilityService.cs:24–30` first reapplies the theme then sets text brushes white for high contrast without changing light-theme backgrounds. On cinema-light this can make text unreadable. Use paired semantic foreground/background resources or platform high-contrast palettes. Typography43–62 walks all realized descendants synchronously and captures inherited baselines after parent changes, risking compounded scale; verify nested controls, delayed realization, 200% text, and actual system contrast settings. Keep weak-key baseline storage.

48. **P2 — queued toast can dereference an unregistered container.** `ToastService.cs:44–45` checks `_container` then queues a lambda accessing the mutable field; Unregister can null it between check and execution. Capture the target and optionally verify it is still registered/loaded before Show. Keep the centralized toast boundary and make severity/error state consistent across pages.

49. **P3 — theme profile sync retains overrides from a prior profile on optional-load failure.** `ThemeService.cs:735–743` swallows custom override failure without clearing scoped prior overrides; ApplyTheme866 consumes the local overrides. For a profile switch with failed optional request, previous profile's theme remains active. This is preference isolation, not credential exposure. Scope cached overrides; distinguish offline last-known data for this profile from another profile's fallback. Preview972–983 persists local LastTheme on every hover because it calls ApplyTheme752–754; preview should not write disk until commit.

### Additional findings from completed Settings/XAML review

50. **P2 — rebuilding library settings retains discarded visual trees.** `Views/SettingsPage.xaml.cs:2485–2488` rebuilds all library cards on every collection change, including reordering;2510 clears only the container. Each new card adds three anonymous handlers to the retained library VM at2666,2717,2791, capturing old badge/text/expand-panel visuals. None are detached. Repeated moves multiply handlers and retain removed controls and their children. Use declarative bindings or disposable per-card subscriptions; measure repeated reorder/navigation allocation and verify old cards collect.

51. **P3 — subtitle preview omits selected appearance settings.** `SettingsPage.xaml.cs:3072–3135` renders font/box/position but never applies outline, shadow, or outline color; lower-third3132 renders at vertical center. The preview cannot predict these settings' actual player effect. Share a preview renderer with the supported subtitle style model or explicitly label unsupported preview attributes.

52. **P2 — home-section reorder has no keyboard action.** `SettingsPage.xaml.cs:3214–3228` exposes a button named Drag and handles DragStarting, with drop processing3326; no click/keyboard move command exists, unlike library ordering's move affordances. Keyboard users can focus the grip but cannot reorder the home configuration. Add Move up/down commands with names and disabled boundary states.

53. **P2 — cached settings never reconnects import updates on re-entry.** Settings uses required navigation cache113 and stops import events on navigation-away302. `EnsureImportTabLoadedAsync:4093–4094` permanently sets its one-time flag; subsequent entry returns before StartImportEventSubscription4106. Therefore leaving and reopening Imports stops its advertised live updates. Conversely, a first load completing after navigation-away starts the subscription after teardown. Separate data initialization from active-page subscription lifetime and guard both by navigation generation.

54. **P2/P3 — room action glyphs lack accessible action names.** `WatchTogetherRoomPage.xaml:182–185,306–323` uses raw glyph Content for clear, delete and promote, and a vote count plus glyph for voting, without AutomationProperties.Name/tooltip. These do not convey the action and target to a screen reader, and raw glyph strings rely on the current font rather than explicit FontIcon. Use named icon buttons such as Remove suggestion, Start title for everyone and Vote for title; verify native automation peers.

55. **P2 conditional — fixed centered auth forms can hide actions in short or enlarged-text windows.** The complete XAML review found no ScrollViewer around `SignupPage.xaml:31`, `ActivateDevicePage.xaml:31`, `InviteClaimPage.xaml:43`, `ProfileSelectPage.xaml:30`, and `ServerSelectPage.xaml:18`, whereas Login provides one34. When their content exceeds available height, action controls can be clipped rather than scrollable. Add a constrained scrolling form container and validate the actual host minimum size and 200% text. Signup's Back to login200–206 is also gated by ShowSignupForm, so the signup-disabled state45 has no page-level escape link; host navigation mitigation was not verified.

56. **P3 — secondary forms inconsistently associate labels with inputs.** Many inputs have only a neighboring TextBlock, for example RequestBrowse media type/sort36–37, WatchTogetherJoin room code189–199, and Settings webhook fields1913/1923/1927. No header, LabeledBy, or explicit automation name binds the label in those declarations. Keep the ebook and notifications XAML's explicit names; apply the same pattern to generated settings forms and confirm actual accessibility peers before declaring accessibility complete.
