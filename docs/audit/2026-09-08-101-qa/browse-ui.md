# Browse, shell, cards and dialogs audit — .101 multigpu preview

Audit date: 2026-09-07/08. Workspace: `D:/SiloPlayer`, current dirty worktree. The coordinating reviewer verified the published .101 preview PDB hashes against 358 source documents (300 C# and 58 XAML files); the user identified this as the running baseline. This report is read-only. No application interactions, source changes, secret values, or legacy GitLab sources were used.

I would keep the native WinUI/libmpv product and its useful bounded-loading primitives. I would replace the page orchestration and inconsistent asynchronous ownership, then consolidate the duplicated card/catalog implementations. A different UI framework would carry the same request races and state bugs unless those boundaries changed first.

## Findings to fix before a broad rebuild

### B01 — Library advanced/guided mode has a confirmed resource failure

**High priority; verified code plus reported runtime evidence.** [LibraryPage.xaml.cs:1262](D:/SiloPlayer/src/SiloPlayer/Views/LibraryPage.xaml.cs:1262) and [1279](D:/SiloPlayer/src/SiloPlayer/Views/LibraryPage.xaml.cs:1279) retrieve `OutlineButtonStyle` from the page's local `Resources`; it is defined in the application theme at [DarkTheme.xaml:467](D:/SiloPlayer/src/SiloPlayer/Themes/DarkTheme.xaml:467). Adjacent accent-style assignments correctly use `Application.Current.Resources`.

Trigger: switch from guided to advanced filters, or back. The coordinator's redacted current-build crash evidence contains `OutlineButtonStyle` not found from `LibraryPage.AdvancedFilterMode_Click`. The handler changes mode/visibility before all assignments succeed, so the exception is also a partial transition. Use one resource-resolution policy and make this a rendered interaction test. Existing source-presence tests did not protect this path.

### B02 — Home incremental updates are actively throwing in the current build

**High priority; runtime symptom confirmed by coordinator, cause not isolated here.** The coordinator observed the current `home_error.txt` being updated with COM exceptions during collection Add/Move in `MediaItemCollectionReconciler.Apply` at lines 57/64, via `HomeSectionReconciler` line 53 and [HomeViewModel.cs:385](D:/SiloPlayer/src/SiloPlayer/ViewModels/HomeViewModel.cs:385)/[566](D:/SiloPlayer/src/SiloPlayer/ViewModels/HomeViewModel.cs:566).

Keep incremental reconciliation: replacing every row would discard position and recreate artwork. Establish the dispatcher, collection ownership and mounted ItemsRepeater state at each failing operation before changing the algorithm. The evidence does **not** distinguish thread affinity, an invalid collection transition, a control lifetime issue or another WinUI failure. Log operation, row/item identity, generation and dispatcher ownership without signed URLs; reproduce with real bound repeaters and replacement/reorder/dismiss/profile transitions. Pure ObservableCollection tests cannot demonstrate this path works in WinUI.

The coordinator's published LandscapeCard regression passed 12 iterations of 22 images, including 139 stale-unload cases and detach cleanup. That is useful bounded card-lifecycle evidence, not evidence that Home collection reconciliation or every artwork surface is fixed.

### B05 — Turning autoplay off can still start the next episode

**Verified code race; elapsed timing not reproduced.** [MainWindow.xaml.cs:604](D:/SiloPlayer/src/SiloPlayer/MainWindow.xaml.cs:604) changes `_playingNextAutoPlay` and the visuals, then awaits settings persistence at line 611. Stop the local countdown synchronously with the user intent, then persist independently. The asynchronous initial setting lookup at lines 574–601 also needs an intent generation so a delayed read cannot overwrite a newer click. Test both with delayed settings responses and an injected clock.

### B06 — Changing audiobook group axes during a load mixes labels, results and click meaning

### B08 — Pre-play track/version choices can be reset by a later metadata repaint

**Verified code, conditional trigger requiring a second metadata paint.** [ItemDetailPage.xaml.cs:1424](D:/SiloPlayer/src/SiloPlayer/Views/ItemDetailPage.xaml.cs:1424) calls `UpdatePlayButton` whenever a matching watch detail is already present. That method reselects the ranked best version at [4864](D:/SiloPlayer/src/SiloPlayer/Views/ItemDetailPage.xaml.cs:4864), rebuilds audio with an unconditional explicit-index reset at line 4957, and calls the subtitle builder whose `resetSelection` default is true at line 5037/5051.

Trigger: choose a non-default version/audio/subtitle while slow companion metadata is still pending, then a valid later `UpdateUI` occurs. Episode enrichment provides a concrete route at lines 1089–1102 when an older/incomplete response needs inherited series metadata. The later paint overwrites user intent even though the version need not have changed. Separate metadata presentation from a stable pre-play selection state; initialize defaults only when the playable content/version changes. Test delayed enrichment after user selections.

### B09 — Pre-play subtitle preference writes can complete out of order

**Verified code race.** Subtitle rows at [ItemDetailPage.xaml.cs:5143](D:/SiloPlayer/src/SiloPlayer/Views/ItemDetailPage.xaml.cs:5143) update the visible selection, close the flyout, await persistence, then render captured inventory. A second choice can run concurrently. [PersistPrePlaySubtitlePreferenceAsync:5583](D:/SiloPlayer/src/SiloPlayer/Views/ItemDetailPage.xaml.cs:5583) writes without serialization and then updates `_watchDetail` at line 5593 without a request/intent owner check.

Trigger: select A, reopen and select B while A is pending; finish A last. The older completion can overwrite the effective preference and redraw a stale inventory, and unordered server writes can persist A. Capture the target identity, serialize mutations or implement a coalescing latest-intent writer, and only publish state for the current intent. Merely canceling the HTTP await cannot guarantee that a server write was canceled.

### B10 — Subtitle appearance reports automatic saving while silently losing changes

**Verified code; two related state defects.** [SubtitleAppearanceDialog.xaml.cs:181](D:/SiloPlayer/src/SiloPlayer/Controls/SubtitleAppearanceDialog.xaml.cs:181) clears `_savePending` before the request; line 192 silently catches failure without restoring pending state or retrying. Closing at lines 117–123 therefore need not retry the failed change. [SubtitleAppearanceDialog.xaml:261](D:/SiloPlayer/src/SiloPlayer/Controls/SubtitleAppearanceDialog.xaml:261) tells the user settings are saved automatically.

In addition, `LoadAsync` sets `_loading = false` at line 150 before its caller runs `SyncAllFromState` at line 114. That sync sets ToggleSwitch/Slider properties at lines 305–306; their handlers at lines 383–395 schedule a save when the value changes. Merely opening with inherited non-default values can create an explicit profile-device override. Reset deletes the override then does the same sync at line 414, which can immediately schedule recreation of the override. Pending 400 ms saves, reset and close are not serialized.

Replace this with one settings editor controller that owns initialization suppression, immutable pending value, local preview, save serialization, retry/error state and flush/reset semantics. Disable or retain edits made during the initial load. Test open without editing, inherited defaults, reset that changes toggle/opacity, write failure, close during write and out-of-order delays.

### B11 — Watch Tonight permits overlapping actions against a mutable card index

**Verified race structure; storyboard overlap must be reproduced in WinUI.** [WatchTonightDialog.xaml.cs:1166](D:/SiloPlayer/src/SiloPlayer/Controls/WatchTonightDialog.xaml.cs:1166) and line 1174 each start a 260 ms exit animation without disabling actions, claiming an action owner or capturing the selected item. Each storyboard invokes its callback at line 1103. Skip increments `_topIndex` at line 1126; Like eventually reads `_cards[_topIndex]` at lines 1137–1138.

Trigger: Skip followed quickly by Like, or repeated Skip/keyboard repeat, before the first exit completes. Competing callbacks can advance multiple cards or accept the subsequent card rather than the one shown when the user acted. Gate one decision per displayed card and capture the card identity in the accepted action. Cancel/invalidate pending callbacks when closed or reset. Fetch at line 265 also has no dialog-lifetime owner, so a late response can repopulate the cleared, closed dialog; cleanup is not cancellation.

### B12 — Match dialog re-enables Apply while an earlier match is pending

**Verified code.** [MatchItemDialog.xaml.cs:72](D:/SiloPlayer/src/SiloPlayer/Controls/MatchItemDialog.xaml.cs:72) disables only Apply before awaiting the mutation at line 84. Selecting another candidate at lines 691–708 unconditionally enables Apply again. There is no `_applying` guard in the handler.

Trigger: Apply candidate A, select B while the server is slow, then Apply B. Conflicting mutations can overlap and either completion can close the dialog. Give the mutation a pending state, block conflicting selections/applications or queue the intended replacement explicitly, and keep the dialog open with the submitted identity and result. Preserve its useful detailed candidate evidence and applied-success-only caller refresh.

### B13 — Cancel in a direct-download dialog does not cancel the transfer

**Verified code.** [ItemDetailPage.xaml.cs:3437](D:/SiloPlayer/src/SiloPlayer/Views/ItemDetailPage.xaml.cs:3437) owns a file picker, HTTP copy and destination stream with no cancellation token or progress model. The destination is truncated at line 3469 before the copy completes. Dismissing the dialog does not cancel the active copy; failures leave a partial destination, including after a user approved replacing an existing file.

Move this to an owned download job with progress and explicit cancel semantics. Download into a temporary destination and commit only after successful completion where supported; preserve or clearly recover an existing destination. Keep the current behavior that a canceled file picker does not report success and that the dialog waits for a successfully saved file before hiding automatically. The existing source test covers those latter details, not transfer cancellation or atomicity.

### B14 — Canceled Calendar artwork does not resume on cached navigation

Retain rows and loaded images, but track/resume incomplete image bindings on reactivation. The existing Calendar source test explicitly checks cancellation and scope renewal without testing this return journey.

### B15 — Cleared Library filters and pending debounces do not share the page lifetime

**Verified code.** Ordinary changes save state through [LibraryPage.xaml.cs:881](D:/SiloPlayer/src/SiloPlayer/Views/LibraryPage.xaml.cs:881). Badge removal at lines 4083–4091 and Clear All at lines 4119–4195 do not save the cleared state. Navigation restoration at line 379 can therefore restore previously saved filters after the user cleared them.

Separately, navigation cleanup at lines 492–516 leaves the year debounce at lines 1667–1681 and advanced-filter debounce at lines 1474–1482/3828–3836 running. Leave within their delay and they can mutate/query a hidden or reassigned page. Stop every pending page callback through one lifetime object; save the entire accepted query atomically after all changes, including clear/reset. Advanced rules are absent from the saved LibraryViewState at lines 74–107 and are not consistently reset with a different library; test cross-library advanced-mode restoration rather than assuming it is isolated.

### B16 — Clicking Home while already on Home displays a failure

**Verified code.** [NavigationService.cs:55](D:/SiloPlayer/src/SiloPlayer/Helpers/NavigationService.cs:55) returns false for duplicate navigation. [MainWindow.xaml.cs:2282](D:/SiloPlayer/src/SiloPlayer/MainWindow.xaml.cs:2282) treats every false return as a rejected Home page and displays “Page failed to open.” Brand navigation at lines 910/916 reaches this method.

Distinguish navigated, already-current and failed outcomes, or make idempotent navigation successful. A no-op is part of the navigation contract, not an exceptional user-visible condition.

### B17 — Empty image results remain cached as an empty BitmapImage

**Verified code, conditional on a null/empty image result.** [UrlToImageSourceConverter.cs:33](D:/SiloPlayer/src/SiloPlayer/Converters/UrlToImageSourceConverter.cs:33) returns a live weak-cached BitmapImage. The population path returns on null/empty bytes at lines 55–56 without removing it; exceptions do remove the cache entry. The stable key at lines 67–68 strips the changing signed query.

Trigger: an image fetch returns no bytes while a control retains that BitmapImage; a later fresh signed URL for the same resource reuses the empty object and does not retry until its weak target is collected. Evict unsuccessful entries and distinguish pending, successful and retryable-failed loads. Do not solve this by keying the durable byte cache on expiring signatures.

## Architecture I would build around

1. **Catalog session:** one immutable query (source/library/media type/facets/sort/profile), snapshot/paging policy, bounded page cache and current viewport. Expose data state independently of WinUI. Library, Catalog, Search results and recommendation grids adapt this session rather than maintain subtly different pagination engines. Preserve the strong active-window tests.
2. **Page lifetime:** one owner for request cancellation, generation, dispatcher publication, event subscriptions, timers and child image bindings. Success, error and finally all follow the same owner rule. Reactivation resumes incomplete resources while preserving stable UI state. Profile identity is part of ownership, not a late global lookup.
3. **Intent-preserving mutations:** a small reusable controller for pending action, immutable target, optimistic state, rollback/error and serialized/coalesced persistence. Reads can be latest-wins; server writes require an ordering policy because canceling a request does not undo an accepted mutation. This directly addresses settings, tracks, pins and match actions.
4. **Media presentation:** pure card/text/badge/action availability models plus a few deliberately different native visual presenters. One artwork service owns cache identity, network/decode budget, failed-load retry and lifecycle. A lightweight library card should inherit the same interaction semantics without inheriting every expensive visual element.
5. **Detail page:** a small coordinator selects a media-family presenter; metadata, episodes, tracks, downloads and matching are deep modules with their own state. Keep rich native layouts. Do not replace a 7,833-line page with many thin files that still mutate the same page globals.
6. **Playback shell:** session-owned behavior in playback services, a shared transport view model, a small active native shell and extracted Subtitle AI workflow. Remove dormant duplicate player UI after extracting active reuse and identifying service calls that were accidentally left attached only to its lifecycle.

Apply these seams incrementally around failing workflows; a one-shot UI rewrite would make it harder to preserve current direct-play behavior, focus, progress, state synchronization and native dialogs.

## Testing and acceptance

The 16 local test files are in the coverage ledger. CurrentHome, CurrentLibrary, CurrentCatalog, MainWindow, GlobalSearch interaction, Hero, Calendar interaction/current, Match, WatchTonight, keyboard, visible-state, RecommendationSection, People/Onboarding and UserDialog tests primarily assert source strings, source ordering or markup constants. CurrentItemCardParity additionally executes a few useful pure display-text cases. These tests are useful narrow architecture checks, but names such as “current parity,” “runtime” or “supports keyboard” overstate what string assertions establish.

Concrete blind spots demonstrated by this review:

- Tests see cancellation and scope renewal in Calendar, but never navigate back with incomplete art (B14).
- Tests see candidate Apply and pending text, but do not select another candidate during the pending write (B12).
- Tests see Watch Tonight playback and close cleanup, but do not run overlapping animations (B11).
- Tests inspect PlayerOverlay's menus/capability gates even though that visual overlay is not activated by the current shell.
- Tests see the LibraryGridCard visual transforms/quick actions, but the keyboard tests exercise other card types (B07).
- SearchRuntimeRegressionTests does not execute SearchViewModel; duplicate-query paging and sort synchronization can pass its textual expectations.

LibraryWindowLoadingTests is a strong exception: the backend reviewer verified real asynchronous VM tests with delayed/canceled responses, first-page publication while a later page is held, overlapping viewport reuse, eviction and page-size caps. Retain and extend them. Its fixture always returns the requested number of sequential items, fixed total 100000 and `has_more=true`, so add shrinking totals, short/duplicate/reordered pages, changed snapshots, transient errors and profile/library replacement. Its VM tests cannot measure native control count, decoding or scroll frame time.

No test run was performed by this reviewer; execution results belong to the coordinating reviewer. No runtime failure is claimed solely because a static test does not cover it. Before marking these surfaces complete, the acceptance pass should include:

- Delayed-response behavioral tests for B03/B05/B06/B08/B09/B10/B12 and stale non-cancellation errors, with controlled ordering rather than timing sleeps.
- WinUI interaction tests for B01/B07/B11/B14, Home bound-collection Add/Move and focus preservation during library slot reuse.
- Realistic large-data profiling of Library, Catalog facets, Home rows, episodes and manga groups: UI-thread/frame latency, realized controls, image work in flight, managed/native memory and cancellation after navigation. Separate first-use XAML construction, decode and network stalls.
- Keyboard-only, Narrator, high contrast, text scaling, reduced motion and narrow/snap-window checks across normal/loading/empty/error/pending states.
- Side-by-side WebUI/native captures against the exact current official GitHub reference recorded by the coordinating reviewer. Compare layout, typography, colors, spacing, responsive transitions, data and every interaction/error state. A pinned fixture commit or matching XAML literal is not a substitute.

## Corrections that prevent overstating this audit

The Home VM undo timer/concurrency concern is not promoted to an active bug because the actual card dismissal route uses MediaItemMenu directly; first establish or restore the intended Undo connection. The ItemDetail VM favorite/watchlist methods have unsafe-looking post-await global access, but the current detail page has default disabled navigation caching and is instantiated with its own transient VM; this report does not claim that an old page's completion demonstrably corrupts a newly navigated page. Same-page subtitle preference concurrency is independently reachable and reported in B09. The old Library letter sampler has not been established as the active letter-navigation path, so its approximate offsets are not a release finding. The dormant PlayerOverlay's geometry/timer/keyboard work is not an active UI performance finding. Runtime freeze magnitude, complete visual parity and accessible-tree behavior remain unmeasured unless explicitly attributed above.
