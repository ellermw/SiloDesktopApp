Give PIN/permission refusals actionable guidance. Add capability-gated `item_metadata_reset` / `mode:reset` with no prior unlock. Match server target-wide reset semantics and update confirmations; preserve independently locked descendants. Old servers retain honestly described legacy behavior or do not offer unsupported semantics. Never fake successful job completion.
2. **Autoplay protection.** Locally persist a threshold default 3, range 0–20, zero off; count automatic advances in the current viewing session, gate both credits and ended countdowns, reset on explicit playback interaction/manual starts, distinguish shuffle triggers and retire stale callbacks. Do not overwrite the profile autoplay preference or apply local advancement to Watch Party.
3. **Current native player HUD.** Match applicable desktop states of upstream #3993 using existing production Lua OSC and owned native menus. Include speed-aware/profile-clock estimated finish time, scrub/pause behavior, thumbhash/artwork loading cover, seek/chapter/rail/menu/post-roll layout. Keep existing reachability, keyboard focus, subtitle details, accent readability and timeline clearance. Phone-specific sheets/portrait layout are not Windows requirements. Compare actual rendered reference and native surfaces before claiming parity.
4. **Featured hero.** Replace fixed height with measured content over the appropriate Home/Library minimum; grow for wrapped titles/actions at narrow/short sizes and text scaling. Remove obsolete Featured eyebrow and its margin; retain carousel navigation/counter and separate collection hero behavior.
5. **Localization foundation and data.** Vendor authoritative catalog source/release with provenance, generate Windows-usable catalogs at development time and ship them offline. Add keyed native message formatting, effective `ui.app_language`, device matching, unknown-tag preservation, nullable Match device, profile/device precedence, safe realtime updates, locale/date/plural formatting and RTL. Preserve machine identifiers and metadata/audio/subtitle language choices. Carry optional server title/default-title/recipe keys and args through copying/reconciliation and resolve only at display boundaries. Retain structured problem field errors and translate at presentation while preserving machine handling and English fallbacks.
6. **Native localization coverage.** Use the foundation on shell/sign-in, Home/library/detail/search/calendar, collections, settings/account/profile, playback/reader and Watch Party. Add only languages whose native resources ship; keep raw server/custom/user text unchanged. Do not infer server title keys from English strings or accidentally persist translated labels. Verify representative reachable controls, profile/language changes, Arabic mixed-direction content, long translations and English fallback.

## Architecture and integration

Core owns contracts and deterministic policies. WinUI owns live language application, direction and display; Player/Lua owns actual video HUD. The native localization API is `AppStrings.Get(string key, IReadOnlyDictionary<string, object?>? arguments = null, string? fallback = null)` in Core, with a scoped locale service responsible for catalog/culture selection and change notifications. Server title rendering takes explicit key/args/raw fallback. Native callers use explicit keys; they do not translate API payloads or arbitrary user data.

Independent work happens in T3-managed worktrees. The lead integrates reviewed commits in dependency order and handles shared-file conflicts. Contracts and hero can proceed independently; autoplay and HUD share playback code and are one worker's ownership. Localization foundation precedes full native coverage and final cross-group localization. Workers do not publish or control the installed player.
