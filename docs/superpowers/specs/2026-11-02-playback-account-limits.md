# Account playback limit presentation

Owner-approved server parity design: distinguish `stream_limit_reached` and `transcode_limit_reached` from server capacity. Match official WebUI titles **Streaming limit reached** and **Video conversion limit reached**; use trimmed nonblank server guidance, otherwise **Stop anything else playing or paused on your account, then try again.** Preserve terminal retryability and fresh-attempt starts after a refusal. Existing capacity errors retain their current wording. No new quotas, general automatic retries or protocol fields. The existing one-shot wait for an in-flight retiring session also covers protocol-v3 account-limit terminals: stream limits for any retiring session, and conversion limits only for a retiring transcode. After retirement, recheck ownership and retry once with a fresh playback attempt; a second refusal is presented normally.
